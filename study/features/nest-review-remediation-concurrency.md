# Nest 正式 Review 修复：并发、任务租约与权限

这篇笔记记录一次后端正式 review 的修复方法，重点是跨进程场景下不能依赖内存锁，也不能只在前端隐藏入口。

## 场景背景

Refresh 请求、AI 额度结算、异步生成任务和公开内容访问都可能同时发生。单实例测试通常看不出问题，真正的风险出现在两个请求或两个 worker 同时读到旧状态时。

## 核心做法

1. **条件更新抢占状态**：先用 `status=PENDING`、`rotatedAt IS NULL` 等条件更新，只有影响行数为 1 的请求继续执行后续业务。
2. **账户字段使用原子增减**：并发余额变更使用 Prisma 的 `increment/decrement`，不要把一次读取的绝对值写回数据库。
3. **异步任务使用数据库租约**：`QUEUED` 或超过租约时间的 `PROCESSING` 才能被认领；处理中定时刷新 `updatedAt`，完成后再结算和写 usage。
4. **失败补偿完整**：provider、对象存储、资产、额度和任务状态放在同一错误处理链中；已创建的文件和对象都要清理。
5. **服务端重新判断权益**：模型、工具、内容引用和文件夹归属不能只依赖页面或导航配置。

## 调用链

```text
请求
  -> 条件更新抢占
  -> 执行业务
  -> 成功写终态 / 失败写终态并补偿

AI 生成任务
  -> worker 认领 QUEUED
  -> 心跳刷新 updatedAt
  -> provider -> 对象存储 -> asset
  -> quota settle -> usage -> SUCCEEDED
```

## 常见错误

- 先读取状态，再无条件更新：两个 worker 都会认为自己成功。
- 用旧余额计算 `nextAvailable` 后绝对赋值：会覆盖并发预占或释放。
- 只删除业务资产，不删除已写入的 `fileAsset` 或对象存储对象。
- 把 `startedAt` 同时当开始时间和心跳时间，导致接口时间含义漂移；本项目用 `updatedAt` 续租。
- 只过滤前端模型列表，后端显式传入任意 `modelId` 仍可调用。
- 给 SSE 接口复用普通幂等响应回放：controller 返回 `undefined` 后可能把空对象保存成重试结果；本项目只校验流式请求带键。

## 手动验证

1. 使用同一个 Refresh Cookie 并发发起两次刷新，确认只有一次成功，另一次返回登录失效。
2. 让两个 worker 同时处理同一个 AI 任务，确认只有一个任务写入成功，失败时额度和临时资产会回收。
3. 用匿名访问公开列表、用普通用户引用草稿或私有内容、连接他人素材文件夹，确认服务端分别隐藏或拒绝。
