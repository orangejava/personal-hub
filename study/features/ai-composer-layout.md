# AI 统一输入框与多类型消息学习笔记

## 场景背景

当一个 AI 平台同时有对话、图片生成、视频生成等工具时，底部输入区很容易在不同页面各写一套。短期能跑，长期会带来三个问题：

- 模型、附件、引用、发送、停止、重新生成的位置不一致。
- 图片/视频参数难以复用，新增工具时还要复制一套表单。
- Chat 的流式消息类型越来越多，页面层容易堆满渲染判断。

本次做法是把“布局骨架、输入区、配置弹窗、消息气泡”拆成四层，让页面只负责把业务状态传进去。

## 核心概念

- 布局组件只管空间：`AiWorkspaceFrame` 只负责消息区和输入区怎么摆。
- 输入组件只管交互：`AiComposer` 只负责输入、快捷键、按钮、清空、优化和发送。
- 配置弹窗用 schema 驱动：`AiConfigPopover` 不知道图片或视频业务，只渲染分组和选项。
- 消息内容用 parts 扩展：`AiMessage.content` 保持兼容，`AiMessage.parts` 用来表达 reasoning、thought_chain、content、source 等结构化片段。
- 气泡组件统一渲染：`AiXBubble` 承接 Markdown、思考过程、思维链和来源，页面不再手动拼展示逻辑。

## 实现步骤

1. 先写 PRD，明确三页统一宽度、空态、快捷键、清空范围、模型下拉和配置弹窗 schema。
2. 抽 `AiWorkspaceFrame`，让 Chat/Image/Video 使用相同布局结构。
3. 抽 `AiComposer`，把模型下拉、引用、附件、发送、停止、清空、语音占位和优化提示词统一收口。
4. 抽 `AiConfigPopover`，把图片/视频参数改成按钮弹窗。
5. 扩展 `AiMessage.parts`，让 mock 流模拟多种响应类型。
6. 增强 `AiXBubble`，把多类型消息渲染从页面层迁移到封装层。
7. 跑 `tsc`、`biome lint`，再用浏览器检查目标页面和控制台。

## 二次布局优化套路

当 AI 创作页需要“底部输入框固定、上方消息列表滚动”时，不建议让整个页面滚动。更稳的做法是：

- 外层 layout 锁定到 `100vh`，内容区使用 `overflow: hidden`。
- 工作区内部用 `grid-template-rows: minmax(0, 1fr) auto`，把剩余高度全部交给消息列表。
- 只让消息容器滚动，输入框区保持在底部。
- 如果消息列表里还有子组件，不要再给子列表额外加滚动条，否则会出现双滚动和滚轮事件抢占。
- 上拉历史可以先在滚动容器的 `scrollTop <= 阈值` 时触发，后续接接口时替换成真实分页请求。

图片/视频这类媒体列表还会多一个右侧筛选工具：

- 搜索输入先用本地草稿保存，回车或失焦后再提交筛选，避免每个字符都刷新列表。
- 时间筛选分为预设和自定义日期范围，页面层保存筛选状态，列表层只负责按状态展示。
- 没有后端接口时可以派生 mock 历史记录，但要把这个边界写清楚，避免后续误以为是真实数据。

## 导航和登录态细化

AI 工具页有自己的专属侧边栏，不应该完全照搬后台管理的菜单形态。本轮把导航拆成“顶级入口 + 创作子项”的结构，有几个可复用经验：

- 如果一组工具天然属于同一类能力，可以让父级只承担展开和分组职责，子项负责真实路由跳转。
- 工具子项进入工作台后自动折叠侧边栏，可以给中间创作区留出更多宽度。
- 返回公开首页这种跨区域动作可以放到品牌名上，避免底部长期占一个固定操作区。
- 登录态入口最好直接复用全局 `@@initialState.currentUser`，AI 余额等业务数据再从 AI model 补充，避免重复拉用户接口。

## 关键代码

`AiMessage` 继续保留 `content`，新增可选 `parts`：

```ts
export interface AiMessage {
  content: string;
  parts?: AiMessagePart[];
}
```

配置弹窗使用“分组数组 + 选项数组”：

```ts
interface AiConfigGroup {
  key: string;
  title: string;
  type: 'segmented' | 'grid';
  value?: string | number;
  options: AiConfigOption[];
  onChange: (value: string | number) => void;
}
```

## 常见错误

- 不要把模型状态放进 `AiComposer` 内部，否则不同工具无法复用后台模型配置。
- 清空按钮不要顺手重置所有参数，本项目约定只清文本、附件和引用。
- 多类型消息不要覆盖旧 `content` 契约，否则复制、历史持久化和旧消息会受影响。
- Ant Design X 的组件状态枚举要以实际类型为准，比如 `ThoughtChain` 使用 `loading` 而不是 `processing`。
- 本地 `pnpm` 可能触发依赖同步确认，校验时可直接运行已有本地 bin。
- 固定视口布局要记得给带 padding 的内容区设置 `box-sizing: border-box`，否则 padding 会把页面撑出可视区。
- 媒体 hover 操作如果拆成顶部和底部两组按钮，要检查旧 CSS 是否还在后面覆盖新样式。
- 前端限制生成数量时，页面参数和 mock/service 层都要做兜底，否则绕过页面状态仍可能生成超出预期的结果。

## 手动验证

1. 打开 `/ai/chat`，输入内容并按 `Enter`，确认输入框清空，消息里出现思考过程、思维链、正文和来源。
2. 打开 `/ai/image`，点击“生成配置”，确认图像质量、清晰度、尺寸、数量、风格都能展示并选中。
3. 打开 `/ai/image` 或 `/ai/video`，点击右侧搜索图标，确认搜索框向左展开，输入后回车能筛选记录。
4. 打开 `/ai/video`，确认底部输入区、模型下拉、生成配置摘要和右侧时间筛选存在，控制台没有 error。
