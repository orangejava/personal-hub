# 内容来源说明与列表批量操作

## 场景背景

内容管理逐条操作在审核积压或清理数据时耗时很长。与此同时，来源提示和授权证明经常被混为一个字段，导致“网络下载，侵权联系”这样的提示被误当成公开授权依据。

## 核心概念

- `sourceNotice`：内容的来源或联系提示，保存于 `contents.source_notice`，可以参与后台关键字搜索。
- `copyrightNote`：提交公开授权依据、解除导入版权闸时使用的说明。非空不等于授权有效，必须保留单独审核。
- 批量操作：前端复用既有单条 API，逐项执行，保留服务端权限、状态和引用校验，并报告失败 ID。批量发布保留已有来源说明；对外可见的受限导入内容要求真实版权授权依据。

## 实现步骤

1. 在 Prisma `Content` 模型增加 `sourceNotice`，用 Prisma schema diff 生成数据库迁移。
2. 在发布 DTO、服务和前端 service 间传递该字段；编辑者提交审核时也要保存。
3. 将来源说明加入列表响应与关键字查询，并在后台列表展示。
4. 在 ProTable 加 `rowSelection` 和批量操作栏；批量发布可以保持原可见性或统一设置目标可见性，按每条内容的导入限制决定是否需要版权说明。分类和标签仍按引用关系禁选。
5. 对逐项结果统计成功数量、失败数量和失败 ID；把写请求限制为小批次并发，不要让 100 行选择同时打满连接，也不要把结果包装成 `code === 0` 信封。

## 常见错误

- 把来源提示写进 `copyrightNote`，会让系统误判已提供授权依据。
- 单纯使用 `Promise.all`，第一次失败就短路并隐藏其他请求的结果；应使用 `Promise.allSettled`。
- 前端批量删除前只做显隐校验不够，单条 API 的服务端约束仍要保留。
- 审核批量通过不能自动填默认版权说明；如同一份真实授权依据适用于多个受限导入内容，可在确认后统一填写，再只传给需要的审核请求。
- 批量发布若给缺少来源说明的原创内容自动写入“网络下载”，会制造不实信息；省略字段即可保留数据库原值。

## 手动验证

在工作区单条导入内容发布弹窗查看来源提示并提交，再用后台列表按提示内容搜索。批量选择原创与受限导入内容，确认原来源说明不被覆盖，目标改为公开/登录可见时出现版权说明必填；审核批量通过对需要说明的项目也应先要求填写。分类和标签列表仍需检查引用限制与失败 ID。
