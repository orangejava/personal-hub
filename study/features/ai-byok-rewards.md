# AI 自备模型、额度与奖励的实现要点

## 场景

AI 平台同时支持系统模型和用户自备厂商时，凭据所有权、额度扣减和历史可追溯性必须分开处理。登录奖励与签到奖励都写入同一额度账本，因此需要独立幂等键。

## 实现步骤

1. 用用户 ID 约束凭据、模型、会话和用量查询，服务端生成用户模型 ID。
2. 保存 Key 前用公钥加密，服务端解密后再次用数据库主密钥加密；响应只返回 `hasKey`。
3. 解析调用模型时先判定自备模式，再绑定对应凭据；失败直接报业务错误。
4. 用量同时记录 `platformCost` 和 `estimatedPlatformCost`，自建模型估算为未知而不是零。
5. 奖励发放用账户条件更新、唯一幂等键和事务账本；签到记录保存当时的规则快照。

## 常见错误

- 用 `modelId` 直接查询用户模型，忘记加 `userId`，会造成跨用户越权。
- 把“无价格”转换为 0，统计会误导管理员。
- 登录与 refresh 各用一条奖励键，导致同日重复发放；两者必须共用上海自然日幂等键。
- 先写签到记录再加余额，失败时会出现已签到但没有奖励。
- 过期清理只依赖扫描时的快照，会与续租或生成终态竞态；必须先锁预占行，再在事务内校验到期条件和消息状态，结算也要返回是否真正成功。
- 异步任务可能排队超过预占 TTL；QUEUED/PROCESSING 仍持有预占，终态才结算或释放。任务价格按预占快照结算，避免管理员中途改价导致账本不一致。
