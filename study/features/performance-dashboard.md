# 本机性能面板

## 场景背景

上线后要知道页面和接口是变快了还是变慢了，又不想先接一套监控平台。第一期只在浏览器里采集，给后续改版留对比基线。

## 核心概念

- TTFB、FCP、LCP、INP 的整页刷新值用官方 `web-vitals`。INP 不要自己用 `PerformanceObserver` 拼。CLS 按当前页累计，停留期间就会写入，不能把整次访问的位移记到最后一页。
- 路由切换是站内导航，从路径变化记到新页面提交后的下一帧。结束点如果放在 `onRouteChange`，懒加载 fallback 还在时就会被记成「已经打开」。
- 接口分组用路由模板，不存完整 URL、查询参数或用户信息。
- 页面样本和接口样本窗口不同。综合分可以同时引用两边，但不要把它们倒进同一个数组再算一个百分位。
- 有一条有效样本就进入分数。没有样本才显示「数据不足」，并按剩下的权重重新计算。不要改回「不足 3 条不算分」。

## 实现步骤

1. 先写纯函数：路由模板、评分、百分位。这些不碰 React，方便单测。
2. 再写存储：页面进 `localStorage`，接口留内存。写入失败就丢掉这一条。
3. 采集挂到现有入口：`app.tsx`、三个布局、登录外壳、请求拦截器。拦截器只加计时字段，不改成功和失败的原有分支。登录页没有公开布局，计时结束点要单独放。外壳是账号页共用的，页面清单里只有 `/user/login` 会写入样本。
4. 界面最后做，并且懒加载。图表库留在异步包里，由 `/status` 和抽屉里的「更多」加载，不进入口包。
5. 全站汇总不要每个请求写数据库。响应结束后把次数加进 Redis 当前分钟的直方图，worker 每 5 分钟重试已结束小时并写入 PostgreSQL。请求路径上不要等待这次计数。
5. 面板能记数之后，再改汇总导出和重组件懒加载，用同一套数字看入口有没有变小。

## 关键边界

计时 id 放在请求配置对象上，不要放进 `headers`，否则会发到服务端。`localStorage` 配额满时不能抛错，否则性能面板会把正常页面打挂。

## 常见错误

- 从 `@/components/shared` 汇总文件引一个小组件，打包器可能把同文件导出的 PDF、图表一起打进入口。
- 抽屉和完整页各自 `useState` 读同一条 `localStorage`，一边切换时另一边不会动。同一页里要有一个小的订阅，刷新后才只靠 `localStorage` 也不够。
- 把接口 p95 和 7 天 LCP 合成一个「最近样本」列表，口径就和面板对不上。

## 手动验证

首页打开抽屉，再到 `/status`。用页头「主题设置」切换亮色和暗色，抽屉、性能页和提示应一起变。接口列表里不应出现 UUID。

## 汇总重试为什么需要完成水位

Redis 删除和 PostgreSQL 提交无法组成同一个本地事务。先删 Redis 会在写库失败时丢数据；先写库则会有一段“两边都有”的时间。解决方法是让小时行、日累计和完成水位在同一数据库事务提交：worker 清理失败后重试时跳过已经完成的小时，查询先读 Redis 再读数据库快照，排除完成水位之前的 Redis 副本。

清理配置也不等于清理事实。保留期从 1 天改回 90 天，已删除的小时不会重新出现，因此需要保存只前进的实际清理边界，以日行补足更早的日期。日累计必须在删小时之前完成，尤其要覆盖 worker 停机后补跑的旧小时。

开发验证依次覆盖：事务中途失败、Redis 删除失败后重试、两次并发提交、短保留期补跑、保留期从短改长、查询恰逢 worker 提交。可运行 `apps/server/test/metrics-integration.spec.ts`，它使用独立 PostgreSQL 测试容器，不依赖开发数据库。
