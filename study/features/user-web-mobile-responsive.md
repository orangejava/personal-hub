# 用户端移动端响应式适配学习笔记

## 场景背景

公开项目地址可能从简历或手机浏览器打开。移动端适配不能只给桌面布局增加几个媒体查询，还要识别哪些区域是尺寸差异，哪些区域是交互结构差异。

## 核心原则

- CSS 处理容器宽度、间距、列数、换行和安全区。
- React 处理手机/平板/矮屏导航 Drawer、底部操作栏和内容面板 Drawer。
- 使用视口断点，不使用 User-Agent 区分具体手机型号。
- 普通内容页按自然高度滚动；编辑器、AI 和沉浸式阅读页使用 `100dvh` 与明确的内部滚动区。
- 桌面端保留语义明确的最小宽度，例如小册阅读器的 `666px`，移动端通过断点覆盖为可收缩。

## 小册阅读器的设计

宽度数字在 `apps/user-web/src/config/viewport-bands.json`。阅读多栏要同时满足宽度至少 1200 和高度超过 499，因为收起列表、章节、大纲和正文最小宽度加起来接近 1200。更窄或更矮都用底部操作栏。

手机档从「章节」开始，宽度够再放出「大纲」和「收藏」，「更多」始终在。平板直接显示这组固定按钮。章节标题完整换行。先关掉「更多」，再打开章节、大纲或小册列表，避免抽屉套抽屉。

## 常见错误

- 只把多列改成单列，却忘记修改固定 `min-width`。
- 用 `100vh` 固定普通内容页，导致地址栏变化时页面跳动。
- 依赖 hover 展示关键操作。
- 让 Modal、Popover 或代码块以固定宽度撑破视口。
- 在多个页面分别读取 `window.innerWidth`，造成断点规则不一致。
- 只按手机断点处理 AI Composer，忘记 992–1200px 也可能因侧栏和右侧工具栏挤压输入区。
- 让输入区的 `Space` 自动换行后再测量溢出，测量会误以为布局正常，按钮就会掉到第二行。
- 把覆盖写进更早加载的全局样式。`ai-components.less` 由布局后加载，同等优先级时后出现的 `flex-wrap: nowrap` 和 `width: 184px !important` 会赢；模型选择上的 `flex: 0 0 184px` 也要在同一处改掉。

## 手动验证

使用浏览器设备模式依次检查 375px、390px、430px 和 768px；打开公开导航 Drawer、小册章节 Drawer、大纲 Drawer，切换章节后确认滚动恢复、底部操作栏和上一章/下一章仍然可用。
