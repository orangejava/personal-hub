# 全站性能汇总

分钟计数进 Redis，小时和日汇总进 PostgreSQL。公开接口只返回聚合数字。

- `POST /api/v1/metrics/web-vitals`：匿名、限流，只接受与前端页面清单一致的固定模板。浏览器在页面隐藏时用 `sendBeacon` 上报；抽样配置未返回时不上报，样本只取当前标签内存。
- `GET /api/v1/metrics/overview`：`24h`、`7d`、`30d`。管理接口不出现，认证接口显示为「认证」。小时保留期不足时，以日行补足较早日期；边界日期按整日近似。依据持久化的实际清理边界选表，延长保留期不会隐藏此前的日行。先合并直方图，再算 p50 / p95。
- `GET /api/v1/metrics/sampling`：只返回抽样比例。
- 耗时中间件在响应结束后计数，不等待 Redis。健康检查和指标接口自己不记。
- 分钟桶保留 48 小时；`server-worker` 启动时及每 5 分钟收口已结束的小时。失败时保留分钟桶供下次重试，锁由持有者在结束时释放。仍需监控连续超过 48 小时的汇总故障。
- 每个小时按时间顺序在数据库事务中写小时行、累加日行并推进 `metric_rollup_state.closed_before`。行锁保证 Redis 锁租约失效后仍不会重复累计；失败整小时回滚，Redis 清理失败可安全重试。
- 概览先读 Redis，再用数据库一致性快照读取日/小时行和完成水位，排除水位之前的 Redis 副本。Redis 不可用时 `partial=true`。
- 按 `ops.metrics.hourRetentionDays` 删旧的小时行，仅清理已入日表的数据，并保存只前进的 `hours_since`。短保留期补跑和延长保留期都不会漏掉日行。日行留下。直方图的 `120000` 档代表 `>5s`，不是精确的 120 秒。
- `GIT_SHA` 有值时，进程启动记一条发布标记。同一个提交号不重复插入。

后台「性能汇总」页可以改抽样百分比和小时保留天数。这组配置不进公开站点对象；保存时提交页面加载到的版本，冲突由服务端拒绝。

页面模板来自 `packages/shared-types/metrics-pages.json`，服务端通过可直接加载的 JSON 子路径使用，避免 CommonJS 生产运行时加载未经编译的共享 TypeScript。匿名 Beacon 不启用业务幂等键（它没有用户身份，且一次文档每个页面最多排队一次）；服务端仍限制模板、数值和按 IP 限流。

代理 IP 的受信范围、专用网络和发版顺序见 [生产 runbook](../../../../../docs/deploy/production-runbook.md)。这会同时修正登录限流、匿名 AI 和审计中原来记录为代理地址的 IP。
