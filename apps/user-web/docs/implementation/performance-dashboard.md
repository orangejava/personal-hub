# 性能面板一、二期

> 状态：一期前端采集与二期 Nest 汇总已完成并验收
> 最后更新：2026-10-16
> 需求：[performance-dashboard-prd.md](../../../../docs/prd/post-launch/performance-dashboard-prd.md)

## 做了什么

公开顶栏、AI 顶栏和工作区顶栏都有性能图标，打开右侧抽屉看当前页评分和本次会话最慢的 5 个接口。完整页是 `/status`。采集覆盖公开页、AI、工作区和登录页。登录页没有这三个顶栏，计时结束点在 `AuthPageShell`。这个外壳也包着注册、找回密码等账号页；页面清单只有 `/user/login`，其它账号页不写入样本，也不会出现在 `/status`。

页面 Web Vitals 进 `localStorage`，保留 7 天。同一页面同一指标最多 8 条，总数仍不超过 200 条，避免连续上报挤掉已经打开过的页面。打开过一次就展示这次记录；某个指标从未记到才显示「数据不足」，并按剩余权重重新归一。接口耗时只留在内存里最近 500 条，刷新后清空。两套窗口不混成一个样本集：综合分里的接口 p95 用会话记录，LCP 等用 7 天记录。整页刷新的 TTFB、FCP、LCP 用 web-vitals。站内跳转浏览器不会重报这些值，所以另记：主区域内容出现的时间当作 FCP 和 LCP，这一跳第一笔新请求的首字节当作 TTFB，布局偏移按当前页累计。位移会在停留约 400ms 后写入，离开页面时再立刻收口，不用等下一次跳转。没有新请求的跳转仍然没有 TTFB。顶部综合分含页面加载和接口 p95，不含路由切换和首屏 JS。

## 调用链

1. `app.tsx` 启动 `web-vitals`，并在 `onRouteChange` 记下路由开始时间。
2. `PublicLayout`、`AiLayout`、工作区 `childrenRender`、登录 `AuthPageShell` 用 `PerfRouteMarker` 包住页面。子页面提交后的下一帧结束计时，避免把懒加载 fallback 当成已经打开。登录不走公开布局，结束点放在登录外壳里。
3. `requestErrorConfig` 只在请求配置上记开始时间，在成功解包或错误处理里记结束。不改解包、toast 和 401 跳转。同一请求只记一次。
4. 分组名是「方法 + 路由模板」。查询参数去掉，UUID 和纯数字段换成 `:id`。

性能面板和提示都跟随站点深浅色，不再单独保存一套面板主题。

图表从 `/status` 再懒加载 `@ant-design/plots`。抽屉里点「更多」才加载同一份图表，快速视图本身不带图表库。蒙层保持半透明，面板底色不铺到蒙层上。

`/status` 用本机、全站、Lighthouse 三个切换。生产实验室记录只在 Lighthouse 里，按日期接在下面。每个日期下用三张卡片写测试条件、待优化、实测摘要；宽屏并排，窄屏上下排。卡片正文默认三行，超出才显示「更多」。两轮共用一张表：一行一个页面，格子内左为桌面、右为手机，各自保留颜色，表头居中。前面是性能分、FCP、LCP、CLS、TBT，其余指标在右侧，横向滚动查看。每个列标题都有说明。10 月 10 日和 10 月 14 日都已按原始报告填入。全站的页面指标、接口和发布标记超过 15 条才分页。发布标记只有容器带了 `GIT_SHA` 才会出现。

`/status` 可以在「本机 / 全站」之间切换。全站读 `GET /api/v1/metrics/overview`，本机仍用原来的 localStorage。首页大分数继续只用本机。离开页面时，拿到后台抽样比例后才决定是否用 `sendBeacon` 上报当前页的五项 Web Vitals，失败不弹提示。同一次打开里每个路由只上报一次；Beacon 只取当前标签内存里的指标，不读其他标签共享的 localStorage。全站页用「上报」「汇总」提示说明抽样和写入节奏：当前小时留在 Redis 并马上显示，worker 启动时先处理一轮，之后每 5 分钟重试已结束小时，Redis 计数保留 48 小时。页面指标、接口、发布标记用主色、辅色、强调色区分；接口状态和两边的 p95 再按良好、待改进、差上色。加载层出现时会暂时关掉页面滚动，避免白屏旁边露出滚动条；站内滚动条轨道透明，滑块跟随亮色和暗色主题。

首页技术栈后面有一段摘要。大分数计入展示的八项：LCP 25、TTFB 15、CLS 15、INP 15、FCP 10、接口 p95 20、路由切换 15、首屏 JS 10。没有样本的项从分母拿掉。八项都有数时分母是 125。这一分和 `/status` 首页卡片不同，卡片仍只看 LCP、TTFB 和路由切换。格子按良好、待改进、差使用和性能面板相同的状态色。没有样本的格子写「数据不足」，保持中性底色。图表、接口列表和页面筛选不放进首页。

## 首轮入口优化

`app.tsx`、`PublicLayout` 改为直接引入 `PageTransition`。顶栏账户入口和各页面也不再从 `@/components/shared` 汇总文件引入，否则打包仍会把同文件导出的 PDF、图表打进页面依赖。内容详情里的 PDF / Word 预览改为打开时才加载。工作区主题抽屉 `SettingDrawer` 只有工作区布局会渲染，公开页不挂它，所以改成打开该布局时再加载，不再留在公开页入口的静态依赖里。

2026-10-07 生产构建：

| 资源 | 结果 |
| --- | --- |
| 入口 `umi.js` | 原始 1.75 MB，gzip 555 KB |
| `pdfjs` | 不在入口。只在内容详情的异步包，gzip 约 136 KB |
| `@ant-design/plots` | 不在入口。只被 `/status` 的异步包引用 |

文档里的基线是 2026-09-29 的入口 gzip 1.16 MB。那之后 main 还有别的提交，这次差额不能全部算成这一轮优化。可以确认的是：入口里没有 pdf 和图表库，采集代码在入口包内，图表在 `/status` 的懒加载包里。

## 故意不做

告警、第三方监控、Nginx gzip / 缓存、管理端采集不在本期范围。

## 手动验证

1. 打开首页，点顶栏性能图标。抽屉里应看到当前页指标；接口名不应带具体 ID。
2. 用页头「主题设置」在亮色和暗色之间切换。抽屉、`/status` 和提示一起变色，刷新后仍跟随站点主题。
3. 用 390px、820px、1280×480 看 `/status` 和抽屉。页面本身不出现横向滚动条。

会话抽样保存随机分位，不缓存旧比例下的布尔结论；页面刷新取得新配置后按新比例判断，0% 停用、100% 全收。模板统一来自共享 JSON。Lighthouse 说明在缺少 ResizeObserver 时退回 resize 监听，仍支持展开和收起。
