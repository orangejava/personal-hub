# 用户端移动端响应式适配

> 状态：已完成首轮实现
> 最后更新：2026-09-23
> 范围：公开前台、公开布局、小册阅读器、工作区统计卡片和 AI 工作区基础布局

## 目标

用户端需要同时保持桌面端既有体验，并在手机浏览器中完成公开首页、内容浏览、阅读器和登录入口的主要流程。实现把样式尺寸和结构交互分开：响应式 Less 负责排列与尺寸，React 只负责手机端 Drawer、Action Sheet 等结构差异。

## 关键改动

- 视口数字以 `src/config/viewport-bands.json` 为准。JS 读 `useViewportBand`。Less 媒体查询手写同一组数字：手机 ≤767，平板 768–991，桌面 ≥992，Chat 常驻会话栏与阅读多栏从 1200px 开始，阅读多栏还要求高度 >499。
- `PublicLayout` 在手机、平板和矮屏把菜单按钮放在 Logo 左侧，并用 Drawer 打开导航；桌面正常高度保留顶栏链接，避免紧凑视口依赖横向滚动。退出紧凑档时主动关闭 Drawer，防止再次缩窄后自动重开。
- 内容详情和小册在阅读底栏模式共用 `ReaderActionBar`。手机档按剩余宽度把按钮收回「更多」；平板使用固定按钮组。宽且高的桌面仍用侧栏和标题下按钮。
- 小册窄屏隐藏侧栏和阅读进度条，进度仍在后台写入。章节、大纲、小册列表各自打开 Drawer；先关「更多」再开下一个。
- AI 输入栏在手机整档使用紧凑底栏：模型、配置或高级设置、发送、更多。放不下时先把配置收进更多，不把按钮挤窄。除观察容器尺寸外，每次动作或配置摘要重渲染后都会复测 `scrollWidth`；图片/视频用稳定的配置摘要作为 `layoutKey`，摘要变短时也会清掉旧阈值并重新探测，避免长期停在错误模式。两页还补了与对话相同的上传附件入口，上传本身仍未接入。
- AI 桌面窄档（1200px 以下）先让文本参数变成两列、900px 以下变成一列；图片/视频 Composer 保持单行测量，实际放不下时复用「更多」收纳，避免按钮自动掉到第二行。
- Chat 在 1200px 以下把会话历史放入独立左侧 Drawer，消息区顶部常驻“对话”、当前会话标题和新建按钮；1200px 以上继续使用原有常驻左栏。选择或新建会话会关闭 Drawer，切回宽桌面也会清理浮层状态。
- 高级设置在各宽度都是对话框，保存才写回，遮罩关闭丢弃草稿。弹窗按内容自然展开，整体最多占视口高度的 88%，真正超高时只滚动正文，footer 不覆盖 System Prompt。访客次数用完或必须登录时才弹窗，不再固定占在输入框下面。
- 阅读底栏生效时统一抬高 BackTop；从紧凑阅读档切回多栏后关闭大纲等浮层，避免跨断点保留旧状态。
- 欢迎区外层高度与历史列表一致，欢迎内容居中且背景与列表相同。
- 登录、注册、找回密码等认证页左上角有返回。登录页窄屏第二行是「忘记密码」在左、「注册」在右。

## 调用与状态流

```text
视口断点
  ├─ CSS：间距、列数、最小宽度、滚动和安全区
  └─ PublicLayout：手机、平板或矮屏渲染移动端导航 Drawer

小册移动操作
  底部操作栏 → Action Sheet / 章节 Drawer / 大纲 Drawer / 书册 Drawer
  → 复用原有章节跳转、滚动恢复和阅读进度逻辑
```

## 验收

至少检查 375px、390px、430px、667px 横屏、768px 和桌面宽度。普通页面使用自然高度；阅读器、AI 和编辑器使用 `100dvh` 或内部滚动，并确认固定底部操作区不会覆盖正文。
