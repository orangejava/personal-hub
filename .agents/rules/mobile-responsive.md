# 移动端响应式开发规则

用户端页面默认需要同时满足桌面端与移动端体验。新增或修改页面、布局、共享组件和交互时，计划中必须说明移动端行为。

视口数字的唯一来源是 `apps/user-web/src/config/viewport-bands.json`。JS 用 `useViewportBand`。Less 的 `@media` 不能读 JSON，必须手写同一组数字，并在规则旁注明来源。不要用 User-Agent 决定布局。`pointer: coarse` 只用于大约 44px 的点击热区。

## 宽度档

| 档 | 宽度 | 约定 |
| --- | --- | --- |
| 手机 | ≤ 767 | 整档同一套紧凑交互，不再在手机内部另切一刀 |
| 平板 | 768–991 | 顶栏链接放得下就保留；放不下时抽屉上收到平板，手机跟着走 |
| 桌面 | ≥ 992 | 保持桌面导航和页面结构 |

某一档放不下时，这一档和更窄的档都用同一套紧凑界面，不要只改更窄的一档。

## 高度与阅读

- 矮屏：高度 ≤ 499。
- 阅读多栏只在宽度 ≥ 1200 且不是矮屏时使用。手机、平板、矮屏都用底部操作栏。
- 底部按钮不要被 flex 压到约 44px 以下。手机档按剩余宽度把放不下的按钮收进「更多」；「更多」始终保留。进入平板后用平板的固定按钮组，不再沿用手机的逐个放出算法。
- 从「更多」打开下一个抽屉前，先关掉「更多」。

## 交互与内容

- 桌面导航、侧栏和阅读目录在紧凑档使用 Drawer、底部操作栏或对话框，不能依赖横向滚动或 hover。
- 标题按场景设置单行或两行限制；正文标题保留完整内容。长 URL、文件名和代码使用 `overflow-wrap: anywhere`。
- 图片、视频、iframe 和代码块不能撑破视口；Markdown 表格必须有明确的横向滚动容器。
- 固定底部元素需要预留 `env(safe-area-inset-bottom)`。
- AI 输入栏放不下时把按钮收进「更多」，不要把按钮或模型选择挤窄。模型在手机档不窄于 JSON 里的 `modelPhoneMin`。

## 验收

- 验收记录必须写明测试过的视口尺寸、关键操作和桌面端回归结果。
- 必须检查横向溢出、Drawer/Modal 越界、标题遮挡、键盘遮挡、固定操作区和控制台错误。
- 若某个页面暂不做完整移动端适配，必须在交付说明中明确记录后续范围。
