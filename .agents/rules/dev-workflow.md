# 开发工作流（短约束）

## 先规划，后改代码

- 动手前用中文说明：现象/目标 → 原因/限制 → 方案 → 计划改动的文件 → 验收通过/故意忽略
- 需求不清先澄清；未说明思路、用户未确认前不直接大改代码
- 涉及 Nest / API / Prisma / api-client / Umi request / mock 时，计划必须符合 `.agents/skills/fullstack-impact/SKILL.md`（全局解包、文件级清单、忽略项写后续阶段）

## 安全增量

- 只改与需求直接相关的文件；不顺手重构无关代码
- 改共享组件 / 工具 / store / 请求封装前，先确认调用方与既有行为
- 优先沿用项目内已有模式，不随意换底层 API 或组件约定

## 改后自检

- 原有交互仍可用；布局不挤压固定操作区
- 前端改动尽量验收；无法浏览器验收时说明原因并给手动步骤
- 交付时写清影响点与 2～3 步验证路径

## 语言

- 对用户说明默认中文
- 关键逻辑用中文注释说明「为什么」
