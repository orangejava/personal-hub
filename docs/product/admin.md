# 后台管理台

> 状态：🟢 产品与 UI 说明；后台治理、接口与数据以 [Canonical API](../backend/canonical-api.md)、[Canonical 数据模型](../backend/canonical-data-model.md) 和长期 Admin PRD 为准
> 最后更新：2026-09-09

---

## 定位

后台管理台负责整个平台的配置与数据管理。React mock 仍可按 `admin` 展示页面，但未来 Nest 由 Canonical 动作权限和 `OWN/ALL` 范围强制授权；`admin` 与 `super_admin` 的治理边界不可由前端角色判断替代。

后台已拆为独立应用 `apps/admin-web`（本地 `:8001`），路由前缀仍为 `/admin`，与用户端 `apps/user-web`（`:8000`）共用 Nest API。登录页只在用户端；管理端未登录会整页跳到用户端登录，靠 Refresh Cookie 恢复会话。

后续如果公开页面迁移到 Next.js，管理端继续留在 Umi / Ant Design Pro，不必把强交互后台迁到 Next。

---

## 框架选型

**长期口径：后台使用 Ant Design + Pro Components，不重写后台基础组件。**

- 使用 `@ant-design/pro-components` 的 `ProTable`、`ProForm`、`ProLayout` 等组件加速开发
- 与主工程共享 TypeScript 类型、请求封装、认证逻辑
- 用户端与管理端都基于 Ant Design Pro：`apps/user-web` 与 `apps/admin-web`
- 后续如果拆出 `apps/next-web`，后台继续由 `apps/admin-web` 承担，避免把强交互后台迁移到 Next.js 带来额外成本

## UI 布局

```
┌──────────────────────────────────────────────────────┐
│  顶部栏：[站点名] 点击回公开前台        [返回前台]  [头像 ▾] │
├──────────┬───────────────────────────────────────────┤
│ 左侧菜单  │  主内容区（ProTable / ProForm 等）          │
│         │                                            │
│ 运营概览  │                                            │
│ 内容管理  │                                            │
│ ├ 文档列表│                                            │
│ ├ 内容审核│                                            │
│ ├ 小册管理│                                            │
│ ├ 分类管理│                                            │
│ ├ 标签管理│                                            │
│ └ 文件管理│                                            │
│ AI 管理   │                                            │
│ ├ AI 配置 │                                            │
│ └ AI 统计 │                                            │
│ 系统管理  │                                            │
│ ├ 用户管理│                                            │
│ ├ 角色管理│                                            │
│ ├ 菜单管理│                                            │
│ ├ 系统配置│  ← 入口卡片：站点 / 首页 / 内容中心 / 关于我 / 项目
│ ├ 主题配置│                                            │
│ └ 操作日志│                                            │
└──────────┴───────────────────────────────────────────┘
```

分组原则：

- 用户管理和角色管理属于系统管理，因为它们控制账号、权限和平台访问边界。
- 文件管理放到内容管理下，因为当前文件主要服务内容预览、封面、附件和后续 AI 资产引用。
- AI 配置和 AI 统计在阶段 5 进入后台，独立为 AI 管理分组；不放进系统配置中心。
- 侧栏分组名是「系统管理」。系统配置中心只收按公开页面拆开的展示配置（站点 / 首页 / 内容中心 / 关于我 / 项目）；子页不单独出现在侧栏。主题配置仍是系统管理下的并列项。
- 旧书签 `/admin/homepage` 重定向到 `/admin/system/homepage`。
- 左上角站点名 / 标题点击返回公开前台首页，不停留在运营概览。后台没有需要「返回」的独立站点首页。

## 各模块详细设计

后台内容、文件、首页、菜单、系统配置与日志的历史 UI/字段决策见 [admin-content-config-prd.md](../history/admin-content-config-prd.md)；后端契约以 Canonical 文档为准。

### 1. 用户管理 `/admin/users`

**列表页**

- **列**：头像、昵称、邮箱、单角色标签、状态徽章（待验证/激活/禁用）、可运营额度余额、注册时间、操作
- **筛选**：角色、状态（激活/禁用）、关键字（邮箱/昵称）
- **操作**：查看详情、启用/禁用账号

**用户详情页 `/admin/users/:id`**

- 基本信息展示（头像、昵称、邮箱、Bio、注册时间）
- 角色分配：**单选**角色；首版用户只有 `users.role_id`，不做多角色或用户直接权限。
- AI 额度操作：
  - 展示账户可用余额、预占与累计使用
  - [增加配额] 输入框（输入正数增加，负数扣减，需备注原因）
  - 操作记录列表来自不可变 `ai_quota_transactions`（时间 / 变更量 / 操作人 / 原因）
- 该用户最近 20 条 AI 使用日志

---

### 2. 角色管理 `/admin/roles`

- **列表**：角色名、标识符（name）、权限数量、是否系统内置、创建时间、操作
- 系统角色包含 `super_admin`、`admin`、`editor`、`member`。`super_admin` 受保护：至少保留一名 `ACTIVE` 所有者，普通 admin 不可降级、禁用、撤销其会话或管理其高风险配置。
- **编辑角色弹窗**：
  - 权限点按 Canonical group 分组展示（内容、文件、用户会话、角色系统、AI 管理）
  - 每组支持"全选"，单独 checkbox 选择
  - 每个权限独立配置 `OWN` / `ALL` 范围；`TEAM` 仅预留，不可授予

权限码是受控 seed（如 `content:update`、`booklet:import`、`user:status:update`、`role:permission:manage`），不能通过后台随意输入字符串。菜单可见性不等同于 API 权限。

---

### 3. 文档管理 `/admin/content`

**文档列表 `/admin/content/list`**

- **列**：标题、类型、分类、状态徽章、可见性、作者、阅读、更新时间、操作；标题旁：`reviewStatus=PENDING` 显示「待审核」，仅版权闸尚未允许公开显示「待审公开」
- **筛选**：类型（全部/小册/PDF/Word/Markdown/富文本/外链）、状态（草稿/已发布/已归档）、分类、作者、关键字
- **操作**：
  - 发布 / 归档。所有者或管理员（`content:publish` ALL）即时发布；导入内容若目标为公开/登录可见，弹窗必填版权说明
  - 设置/取消精选（控制首页推荐）
  - 删除（需二次确认）
- **不再提供**「解除导入限制」按钮。导入版权闸并入内容审核：通过审核或所有者直接发布且目标非私有时清闸

**内容审核 `/admin/content/reviews`**

- **权限**：接口为 `content:publish` ALL（不新增权限码）；侧栏与文档列表一样用 `content:featured` 控制展示，避免编辑者因 OWN 发布权看到后台菜单。编辑者不能打开此页接口。
- **筛选**：待审核 / 已通过 / 已驳回 / 已取消；默认待审核。分页默认 10 + size changer + jumper
- **列**：标题、类型、申请人、申请可见性、状态、导入限制、驳回原因、提交时间、操作
- **操作**：
  - 通过：内容从草稿发布。导入来源且申请公开/登录可见时必填版权说明
  - 驳回：必填原因；内容保持草稿，作者可改后再提交
- **AI 审核（后续阶段，本期不做）**：不调用模型、不自动打分。后续若做，只作为队列辅助建议，不能替代管理员通过/驳回。

**小册管理 `/admin/content/booklets`**

- **列**：小册标题、原作者、章节数、上传者、状态、更新时间、操作
- **操作**：
  - 查看章节结构
  - 重新生成目录
  - 下载原始导入包
  - 删除小册
- **目的**：处理小册这种有明显结构特征的文档资源，不和普通文档操作完全混在一起

**分类管理 `/admin/content/categories`**

- 树形列表，节点显示：分类名、下属内容数、操作（编辑/删除/新增子分类）
- 支持拖拽排序（同级内排序）
- 新增/编辑弹窗字段：分类名（必填）、父分类（可选）、Slug（自动生成可手动修改）
- **分类由管理员在后台手动创建和维护**，不支持用户自建

**标签管理 `/admin/content/tags`**

- **列**：标签名、内容数量、创建者、创建时间、操作（删除）
- 管理员可删除任意标签（删除前显示关联内容数量提示）
- **标签创建权限**：编辑者（editor）可在创建内容时新建标签，直接生效，无需审核

---

### 4. 文件管理 `/admin/files`

- **列**：文件名、MIME 类型、大小、存储位置（local/minio）、上传者、上传时间、操作
- **操作**：预览（图片内嵌/PDF 新标签页打开）、下载、删除
- 支持批量删除（多选）
- **筛选**：MIME 类型（图片/PDF/其他）、上传者、时间范围
- 删除文件时检查是否被内容引用，若被引用则警告不允许直接删除

---

### 5. AI 配置 `/admin/ai/config`

**厂商管理（Providers）**

表格列：厂商名称 / Base URL / API Key 是否已配置 / 启用状态 / 操作

新增/编辑弹窗字段：

| 字段     | 说明                                                                 |
| -------- | -------------------------------------------------------------------- |
| 厂商标识 | 唯一英文标识（如 `aliyun_bailian`）                                  |
| 展示名称 | 如"阿里云百炼"                                                       |
| Base URL | API 基础地址（如 `https://dashscope.aliyuncs.com`）                  |
| API Key  | 仅写入环境变量或密钥管理；后台只显示是否已配置，永不回显明文或脱敏值 |
| 启用状态 | 禁用后该厂商所有模型不可用                                           |

**模型管理（Models）**

表格列：模型 ID / 展示名称 / 所属厂商 / 支持工具 / 对用户可见 / 是否默认 / 操作

新增/编辑弹窗字段：

| 字段       | 说明                                 |
| ---------- | ------------------------------------ |
| 所属厂商   | 下拉选择已配置的厂商                 |
| 模型 ID    | 如 `qwen-turbo`、`gpt-4o-mini`       |
| 展示名称   | 用户看到的名称                       |
| 支持工具   | 多选：chat / text / image            |
| 对用户可见 | 开关（关闭后用户端下拉不显示此模型） |
| 是否默认   | 每种工具类型下只能有一个默认模型     |
| 上下文长度 | tokens 数，如 8192                   |
| 输入价格   | 元/1K tokens                         |
| 输出价格   | 元/1K tokens                         |

**初始化数据**

| 厂商       | 模型 ID     | 展示名称    | 工具      | 默认 |
| ---------- | ----------- | ----------- | --------- | :--: |
| 阿里云百炼 | qwen-turbo  | Qwen Turbo  | chat/text |  ✅  |
| 阿里云百炼 | qwen-plus   | Qwen Plus   | chat/text |  ❌  |
| OpenAI     | gpt-4o-mini | GPT-4o mini | chat/text |  ❌  |
| OpenAI     | dall-e-3    | DALL·E 3    | image     |  ✅  |

### 7. AI 额度账本管理

**首版方案（无自助充值）**：

- 管理员通过需幂等键的额度调整接口增减额度并填写原因；余额不能小于零。
- 邮箱验证成功后由服务端账本一次性授予默认 `10,000` 可运营额度；不在注册阶段、前端或 `users` 字段中直接加数。
- AI 发起时服务端原子预占，完成后按实际用量结算并释放多余预占；失败释放未使用额度，中断按实际用量结算。

**数据结构预留（后续充值功能用）**：

- `ai_quota_transactions`：不可变账户账本，记录授予、预占、结算、释放和人工调整及余额快照
- 后续支持套餐配置 + 支付宝/微信支付对接

### 9. 菜单管理 `/admin/menus`

- 分四类菜单 scope：`public` 前台导航、`workspace` 工作区侧边栏、`admin` 后台侧边栏、`ai` AI 工作台。
- 树形展示，支持同级拖拽排序

### 11. 系统配置中心 `/admin/system`

`/admin/system` 是入口卡片，不直接写配置。核心恢复菜单仍是 `admin.system.config`。权限沿用 `system:config:manage`。

| 子页 | 路径 | 配置组 |
| ---- | ---- | ------ |
| 站点配置 | `/admin/system/site` | `site.general` |
| 首页配置 | `/admin/system/homepage` | `site.homepage` |
| 内容中心配置 | `/admin/system/content` | `site.layout`（卡片样式、阅读宽度、面包屑、Hero 排版） |
| 关于我配置 | `/admin/system/about` | `site.about` |
| 项目配置 | `/admin/system/projects` | `site.layout` 的 `projectsTitle` / `projectsIntro` |

不要把厂商 API Key、模型启停等「AI 管理」运营项，以及主题色混进本中心。AI 工具推荐和技术栈本轮仍留在首页配置，不拆独立卡片。

> 额度赠送在邮箱验证成功时由服务端账本处理；登录安全阈值、密钥、数据库地址等安全/运行配置属于环境变量或密钥管理，禁止通过系统配置页面编辑。

### 12. 操作日志 `/admin/logs`

- **列**：时间、操作用户、操作类型（如 `content:publish`）、操作对象（类型 + ID）、IP、结果（成功/失败）、详情
- **筛选**：操作类型、操作用户、时间范围、结果
- 点击"详情"展开弹窗，显示完整 `detail` JSON
- **分级保留**：安全、权限、会话、额度日志保留 365 天；后台运营和一般业务审计保留 90 天。
- 审计详情使用严格白名单，不记录密码、JWT/Refresh Token、Cookie、AI Key、完整 AI 正文或文件二进制。磁盘 80% 告警；90% 紧急状态下仅 `super_admin` 可按时间/类别、填写原因并二次确认后提前清理。
