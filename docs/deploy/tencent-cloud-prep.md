## 1. 域名和 HTTPS

### 1.1 有域名不等于有 HTTPS

| 问题 | 答案 |
| --- | --- |
| 上 HTTPS 只需要域名吗？ | **不够。** 还要：DNS 解析到这台机、安全组放行 **443**、申请证书、Nginx 听 443。 |
| 要买付费证书吗？ | **不必。** 用腾讯云 **免费 DV SSL**（控制台「SSL 证书」申请，一般一年期）或服务器上 Let’s Encrypt。个人站 DV 就够，不要买 OV/EV。 |
| 租到 `personal-hub` 相关域名就自动 HTTPS 了吗？ | **不会。** 租域名只是拿到名字。解析、备案（大陆）、证书、Nginx 都要另做。 |
| 大陆 CVM 用域名对外要备案吗？ | **几乎一定要。** 未备案域名在腾讯云大陆主机上，80/443 常被拦截。只用 `http://公网IP` **不用备案**。 |

### 1.2 租域名时注意什么

1. **后缀**：`.com` / `.net` 比 `.cn` 省事（`.cn` 必须实名，备案也更严）。想要 `personal-hub.com` 被占用就试 `personalhub.com`、`personal-hub.dev`、`phub.me` 等。
2. **实名**：腾讯云域名注册要实名，一般几小时到几个工作日。
3. **解析**：添加 **A 记录** `@`（和可选 `www`）到 CVM **公网 IPv4**。TTL 先 600 秒。
4. **安全组**：放行 `80`、`443`（来源先用你自己的公网 IP `/32`），以及 SSH。不要对 `0.0.0.0/0` 长期敞开。
5. **备案（大陆）**：域名实名通过后，在腾讯云「网站备案」提交。常见 **7–20 个工作日**。备案期间可以继续用 IP 访问，不必停开发。
6. **改应用**：证书和解析生效后，把 `PUBLIC_APP_ORIGIN` 改成 `https://你的域名`，Nginx 加 `server_name` 和 443。业务代码不用重写。

### 1.3 HTTPS 你要准备的材料

- 已实名的域名
- 解析已指向这台 CVM（浏览器能 `ping` / 解析到正确 IP）
- 腾讯云免费 SSL：**证书 + 私钥**（Nginx 格式），或 Let’s Encrypt 自动签发
- 安全组 443
- 大陆主机：备案通过（否则域名 HTTPS 也打不开）

首版没有域名时：继续 `http://<公网IP>:80`。此时必须在实现刀里允许 HTTP Cookie，否则生产 `Secure` Cookie 会导致登录失败。

## 2. SMTP（注册验证 / 忘记密码要对外发信）

现网代码已支持通用 SMTP。当前无域名方案使用 QQ 邮箱，配置完成后把值填入本地 `.env.local` 或服务器 `.env.prod`，不要写入仓库。

### 2.1 推荐申请方式（腾讯云）

**方案 1（后续可选）：腾讯云「邮件推送」SES**

1. 控制台搜索「邮件推送」→ 开通。
2. 没有域名时：先做 **发信地址验证**（用你自己的 QQ/邮箱收一封验证信）。
3. 有域名后：做 **发信域名验证**（加几条 DNS），`MAIL_FROM` 才能用 `noreply@你的域名`。
4. 创建 SMTP 密码，记下主机、端口、用户名、密码。

**方案 2（当前推荐）：QQ 邮箱 SMTP**

1. QQ 邮箱 → 设置 → 账户 → 开启 SMTP → 生成 **授权码**（不是登录密码）。
2. 主机一般是 `smtp.qq.com`，端口 `465`（SSL）或 `587`。
3. `MAIL_FROM` 必须是这个 QQ 邮箱。

个人站首版用方案 2 即可；以后有域名且需要更稳定的系统邮件，再迁到腾讯云邮件推送。

### 2.2 项目配置

- SMTP 主机
- 端口（465 或 587）
- 用户名
- 授权码 / SMTP 密码
- `MAIL_FROM`（显示名 + 已验证地址）
- 用的是 SSL 还是 STARTTLS

QQ 邮箱推荐配置：

```env
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的完整QQ邮箱地址
SMTP_PASSWORD=16位授权码
SMTP_SECURE=true
MAIL_FROM=Personal Hub <你的完整QQ邮箱地址>
```

本地填 `apps/server/.env.local`，生产填服务器 `.env.prod`。不要把授权码提交到 Git、写入这个文档或发送到聊天。

### 2.3 验证方式

1. 启动 `pnpm dev:server` 和 `pnpm dev:user`。
2. 打开 `http://localhost:8000/user/register`，用另一个真实邮箱注册。
3. 检查收件箱和垃圾邮件，确认收到「验证你的 Personal Hub 邮箱」。
4. 点击邮件链接完成验证。
5. 在登录页点击「忘记密码」，再次确认能收到密码重置邮件。
6. 检查服务端日志：只能看到 SMTP transporter initialized，不得出现授权码。

如果失败，先检查 QQ 邮箱「授权码管理」中授权码是否仍有效，再确认 465 对应 `SMTP_SECURE=true`，以及 `MAIL_FROM` 与 `SMTP_USER` 是同一个邮箱。

## 3. 腾讯云 COS（不只是建一个桶）

生产对象存储用 COS 协议，**不要在生产 Compose 里再起 MinIO**。Nest 变量名暂时仍是 `MINIO_*`。

### 3.0 轻量对象存储 ≠ 标准 COS 控制台（同名会冲突）

轻量应用服务器里的「对象存储」是 **轻量对象存储（Lighthouse 版）**。左侧产品列表里的「对象存储 COS」是 **标准 COS 控制台**。底层都占**同一套账号内桶名**，但**两个列表互不同步**。

所以会出现：

- 在轻量里建了桶 → 标准 COS 列表里看不到
- 到标准 COS 用同一个短名再建 → 提示「存储桶名称已存在」

这是腾讯云预期行为，不是你建丢了。官方说明：[COS 一般性问题](https://cloud.tencent.com/document/product/436/30748)。

**首版建议：继续用轻量里已经建好的那个桶**，到「轻量应用服务器控制台 → 轻量对象存储」里看全名（含 APPID）、地域、访问域名。不要为了「能在 COS 里看见」再删再建。

若坚持要在标准 COS 控制台管理：换一个**从未用过的短名**新建（例如 `personal-hub-prod` 被占就用 `personal-hub-web-prod`），或删掉轻量里的空桶再在 COS 建同名（有文件先迁走）。两种桶合计上限约 200 个/主账号。

轻量版支持 COS SDK 做对象读写，和本项目预签名上传兼容；生命周期、版本控制、跨区域复制等高级能力只有标准 COS 完整。个人站首版不需要那些。

### 3.1 控制台要做的事

| 步骤 | 做法 | 注意 |
| --- | --- | --- |
| 选地域 | 尽量和 CVM **同一地域**（例如都在广州） | 跨地域有流量费、更慢 |
| 建桶 | 名称建议 `personal-hub-prod` | 腾讯会变成 `personal-hub-prod-<APPID>` 这种 **全名**；已在轻量里建过的，到轻量对象存储页抄全名，不要去标准 COS 再建同名 |
| 访问权限 | **私有读写** | 不要「公有读」。浏览器上传走预签名，不需要桶公开 |
| 版本控制 | 首版可关 | 省存储 |
| CORS | 允许你的站点 Origin，方法含 `GET` `PUT` `POST` `HEAD`，暴露 `ETag` | 首版 Origin 是 `http://<公网IP>`；换成 HTTPS 域名后改 CORS |
| 密钥 | 建 **CAM 子用户**，只授这个桶的读写；用子用户 SecretId/SecretKey | **不要**把主账号密钥放服务器 |

### 3.2 命名规范

- 只用小写字母、数字、连字符，3–40 字符左右。
- 推荐：`personal-hub-prod`（生产）、不要用 `test` / `tmp` 当生产桶。
- 不要在桶名里写密钥、邮箱、身份证号。
- 环境变量 `MINIO_BUCKET` = 控制台显示的 **全名（含 APPID）**。

### 3.3 还要准备什么

- 地域 endpoint，例如华南：`https://cos.ap-guangzhou.myqcloud.com`（以控制台「概览」为准）。
- 子用户 SecretId / SecretKey。
- 桶 CORS 与安全组无关：COS 是公网 API，CVM 出网要能访问 COS。

当前 S3 客户端会根据 endpoint 自动选择：腾讯 COS 使用虚拟主机风格和地域签名，
本地 MinIO 使用 `forcePathStyle`。仍需按 [production-runbook.md](./production-runbook.md)
完成真实桶的上传、下载、删除和小册导入冒烟。
