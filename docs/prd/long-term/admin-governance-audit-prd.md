> 适用：`apps/server` 的 Admin、User、Role、AuditLog 模块
> 关联：[Auth、会话与 RBAC](./auth-rbac-session-prd.md)、[系统配置与菜单管理](./system-config-menu-prd.md)、[内容阅读域](./content-reading-domain-prd.md)

## 1. 目标

后台不是前端页面的“管理视图”，而是对用户、权限、内容、文件、系统配置与 AI 配置执行高风险操作的服务端边界。本模块确保：

- 所有 `/api/v1/admin/**` 接口经过强制身份、权限和数据范围校验。
- 平台始终保留可恢复的最高管理身份，不因误操作锁死。
- 用户禁用、角色变更、会话撤销、内容永久删除、文件删除、Token 调整与配置修改均可审计。
- 后台批量操作具有明确的失败处理、幂等与二次确认语义。

## 2. 管理身份模型

### 2.1 系统所有者

首版引入 `super_admin` 系统所有者身份：

- 仅通过容器内一次性 bootstrap CLI 创建或提升指定邮箱；必须至少存在一个。
- 不能通过普通后台角色管理页面删除、降级、禁用或移除。
- 不用于日常内容运营；普通 `admin` 承担日常用户、内容、配置、AI 管理。
- 后续可支持安全地转移所有者，但必须采用双人确认或近期登录验证，本期不实现。

服务端硬性约束：

1. 任意写操作后，至少保留一个 `super_admin` 且账号为 `active`。
2. 不能由普通 admin 修改 super_admin 的角色、状态、会话或高风险配置。
3. 即使不涉及 super_admin，也不能让最后一个具备后台治理权限的账号被禁用或剥夺权限。
4. 此约束必须在 Service 事务内执行，不能仅由 UI 禁用按钮。

初始化规则：

- CLI 从部署环境变量读取目标邮箱和临时密码，成功后拒绝重复执行；不得存在公开 HTTP 初始化端点、代码默认账号或镜像内固定密码。
- CLI 必须同时写入受保护角色、认证/权限版本和审计记录；首次登录必须修改临时密码。
- 公开注册只会产生 `MEMBER`，不允许通过注册或普通后台角色页获得 `super_admin`。

### 2.2 权限分层

| 能力                           | super_admin | admin                      | editor / member |
| ------------------------------ | ----------- | -------------------------- | --------------- |
| 内容、分类、标签、文件日常管理 | ✅          | ✅                         | 按内容 own 权限 |
| 系统配置、菜单、AI 配置        | ✅          | ✅                         | ❌              |
| 用户启用/禁用、角色分配        | ✅          | ✅（不得操作 super_admin） | ❌              |
| 踢普通用户会话                 | ✅          | ✅                         | ❌              |
| 踢 admin / super_admin 会话    | ✅          | ❌                         | ❌              |
| 管理 admin/super_admin 角色    | ✅          | ❌                         | ❌              |
| 永久删除内容/文件              | ✅          | 需明确 `*:purge:all` 权限  | ❌              |
| 恢复核心菜单与紧急配置         | ✅          | ❌                         | ❌              |

角色是权限集合，表格表示 seed 的默认治理规则；最终 Controller 使用细分 PermissionCode，不使用前端角色字符串判断。

## 3. 用户与会话运营

### 3.1 用户管理

后台用户查询支持：关键词（邮箱/昵称）、角色、状态、注册时间、分页与稳定排序。

用户详情聚合：

- 基础资料和单角色。
- 当前 Token 余额与 Token 交易流水。
- 最近 AI 使用摘要。
- 设备会话列表（脱敏 IP / User-Agent）。
- 最近安全和管理操作日志。

操作：

| 操作       | 后端行为                                                                  |
| ---------- | ------------------------------------------------------------------------- |
| 禁用用户   | 将 status 设为 disabled、递增 authVersion、撤销全部会话、清 Redis、写审计 |
| 启用用户   | 仅恢复账号状态；不自动恢复旧会话                                          |
| 分配角色   | 事务更新 `users.role_id`、递增 permissionVersion、清权限/菜单缓存、写审计 |
| 角色调整   | 校验 super_admin/最后管理员保护，再更新权限版本                           |
| 踢单设备   | 撤销指定 auth_session                                                     |
| 踢全部设备 | 撤销全部 auth_sessions 并递增 authVersion                                 |
| 调整 Token | 事务写 token_transactions 与用户余额，余额不得小于零                      |

### 3.2 高风险操作约束

- 禁用、角色调整、踢全部设备、Token 扣减、永久删除必须由前端二次确认，但服务端不依赖该确认。
- 高风险写接口要求 `Idempotency-Key`，避免网络重试重复扣额度或重复删除。
- super_admin 操作自身或其他 super_admin 时，首版要求先完成密码再验证；服务端签发仅绑定当前会话、动作类别和目标资源的短时一次性 `reauth` 确认 Token，最长 5 分钟。高风险写 DTO 必须携带该 Token，消费后立即失效并写安全审计。
- 已自愿启用 TOTP 的 admin / super_admin 必须完成动态码或恢复码登录。TOTP 绑定、停用、恢复码使用和 super_admin 代为重置都属于高风险审计事件；默认不强制任何角色绑定。

## 4. 后台内容、文件与配置操作

### 4.1 内容

- 全量内容列表可检索作者、状态、可见性、类型、分类、日期。
- 管理员可以代替作者发布、归档、恢复、设置精选与查看导入告警。
- 删除默认仍为软删除；永久删除必须检查版本快照、章节、文件引用和导入源 ZIP 清理任务。
- 对导入小册解除 `PRIVATE_UNTIL_LICENSED` 限制是高风险操作：必须记录授权说明、操作者和时间。

### 4.2 文件

- 文件被内容、封面、AI 资产或导入任务引用时不可直接物理删除。
- 管理员删除是逻辑删除并触发异步引用检查；确认无引用后才删除对象存储文件。
- 批量删除逐项处理，响应必须返回 `deleted` 与 `failed[{id, code, message}]`，不能因单个失败回滚所有无关文件。

### 4.3 配置与菜单

- 系统配置和菜单变更采用已确认的缓存失效、事务与核心菜单防锁死规则。
- AI Provider API Key 是只写字段：日志只记录 provider 标识和字段是否改变，永不记录明文、脱敏 Key 或请求体。

## 5. 操作审计与安全日志

### 5.1 日志类型

| 类型       | 示例                                                      | 保留期 |
| ---------- | --------------------------------------------------------- | ------ |
| 运营日志   | 内容发布、分类调整、首页配置、菜单排序                    | 90 天  |
| 安全日志   | 登录成功/失败、Refresh 重放、密码修改、会话撤销、账号禁用 | 1 年   |
| 权限日志   | 角色创建/变更、权限变更、super_admin 尝试操作             | 1 年   |
| Token 日志 | 赠送、手动调整、扣减、余额变化                            | 1 年   |

过期清理由定时任务批量执行；数据库备份策略与日志保留期独立，不能因备份存在而跳过合规清理。

容量保护：

- 磁盘使用率到 80% 时告警，优先轮转普通运行日志、清理过期缓存和到期审计记录。
- 到 90% 时，只有 `super_admin` 可在填写原因、二次确认后提前按时间/类别清理普通审计日志；该动作本身必须产生新的高风险审计记录。
- 高风险审计日志仅在 90% 紧急状态下按明确范围提前清理；禁止批量无差别清空审计表。

### 5.2 最小字段

```text
id
category              # operation / security / permission / token
action                # content:publish / auth:login_failed 等
actorId               # 允许为空，例如匿名登录失败
targetType
targetId
result                # success / fail / denied
requestId
ipMasked
userAgentSummary
detail                # 结构化 JSON，严格字段白名单
createdAt
expiresAt
```

日志 `detail` 禁止出现密码、JWT、Refresh Token、API Key、完整身份信息、正文和文件二进制内容。

### 5.3 写入方式

- 高风险操作在主事务成功后写操作日志；对安全拒绝/失败事件单独保证写入。
- 日志写入失败不能让已完成的业务事务回滚，但应有监控和重试/告警。
- 用户可见的错误不返回内部审计细节。

## 6. 后台 API 边界

| 模块     | 代表接口                                                               | 关键约束                                        |
| -------- | ---------------------------------------------------------------------- | ----------------------------------------------- |
| 用户     | `GET /api/v1/admin/users`、`PATCH /:id/status`、`PUT /:id/role`        | status/角色变化使旧会话和权限缓存立即失效       |
| 会话     | `GET /:id/sessions`、`POST /:id/sessions/revoke-all`                   | own/all 与 super_admin 层级校验                 |
| 角色权限 | `GET/POST/PATCH /api/v1/admin/roles`、`PUT /:id/permissions`           | 更新权限版本，禁止破坏系统所有者恢复路径        |
| 内容     | `GET /api/v1/admin/contents`、`POST /:id/publish`、`DELETE /:id/purge` | 复用内容状态机与软删除                          |
| 文件     | `GET /api/v1/admin/files`、`DELETE /:id`                               | 引用检查与异步物理清理                          |
| 日志     | `GET /api/v1/admin/audit-logs`                                         | 只读、分页、按 category/action/result/time 筛选 |

所有接口的权限码、DTO、错误码在 [Canonical API](../../backend/canonical-api.md) 统一列出；本文件定义的是治理语义，而非最终前端 mock URL。

## 7. 验收条件

- 普通 admin 无法禁用、降权、踢下线或管理 super_admin。
- 任意 API 操作都无法让系统失去最后一个 active super_admin。
- 用户禁用、角色变更、踢会话后，旧 Access Token 的下一次受保护请求立即被拒绝。
- 批量文件删除可报告部分成功/失败，且不会删除仍被引用对象。
- 高风险后台操作、权限变更、安全失败和 Token 流水按对应保留期记录。
- 审计日志不泄露密钥、Token、密码、正文或二进制文件。
- super_admin 高风险操作必须验证一次性 reauth Token；重复、过期、跨会话或跨目标使用均被拒绝并记录安全审计。

## 8. 模块实施前契约清单

- 为用户、角色、会话、内容、文件、配置和 AI 管理接口补齐 OpenAPI DTO、错误码、分页/批量部分成功响应。
- 每个 Admin Controller 必须映射受控 PermissionCode；数据范围、super_admin 层级与最后治理账号约束在 Service 事务中验证。
- 高风险动作统一要求 `Idempotency-Key`，并在需要时要求本文件定义的 5 分钟一次性 reauth Token。
- 为权限即时失效、最后一个 super_admin、批量文件部分失败、审计保留及磁盘阈值写 HTTP E2E / 集成测试。
