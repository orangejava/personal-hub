# 后台素材库与工作区用户素材库 PRD

> 状态：需求细化稿；统一入口、AI Tab、超级管理员私有访问和回收站规则已确认；真实图片/视频能力仍在 `ai-admin` worktree
> 最后更新：2026-10-29
> 关系：细化 [phase-2/asset-library.md](../../product/phase-2/asset-library.md)，并连接 [ai-tool-experience-prd.md](./ai-tool-experience-prd.md)、[ai-media-generation-prd.md](./ai-media-generation-prd.md)、[工作区内容生命周期优化](./workspace-content-lifecycle-optimization-prd.md) 和文件域契约

## 1. 目标

建立一个用户视角的统一素材库和一个后台管理视图，底层使用同一资产目录与权限/引用规则。用户素材库收纳当前用户的 AI 图片、视频、文本结果、完成的对话引用、主动保存的对话快照，以及上传附件、参考图/视频、资料包文件；后台管理视图负责站点运营素材。用户私有素材仅系统超级管理员可在专用受审计入口查看。

两套入口分别是：

- 工作区用户素材库：路由 `/workspace/assets`，唯一的用户完整管理页面；以 Tab 区分“全部”“AI 生产素材”“我上传的”“参考素材”等来源，用户只能看到自己有权访问的项目。
- 后台管理素材库：普通管理员只看站点运营素材和被配置引用的资源；系统超级管理员另有“用户私有素材”入口，可按用户检索并在受审计条件下查看。普通管理员不能通过已有 `ALL` 数据范围或猜测 ID 绕过这一限制。

### 1.1 当前基线，避免把已有能力误写成未开发

当前已有 `/ai/assets` 页面、`/api/v1/app/ai/assets` 接口、`AiAsset`/`AiAssetFolder` 模型、AI 生成任务写入图片/视频资产、收藏、文件夹和 AI 页内的回收站筛选。它是 **AI 资产基础页面**，尚不是覆盖所有上传文件、对话引用、资料包、统一回收站、后台站点素材和超级管理员私有访问的完整素材库。`/workspace/assets` 目前不存在。现有 AI 页可以创建不关联真实生成任务的文本资产；迁移时要把这类记录标记为“手动保存/历史”，不能因 `source=GENERATED` 就当作真实模型产物。当前 AI 页的 `DELETE /app/ai/assets/:id` 只写 `deletedAt`，且不要求先 `TRASHED`；统一回收站上线前须收口这条绕行路径。

## 2. 资产模型

以下是目标查询模型，**不是当前 Prisma 已有字段清单**。现有 `AiAsset` 已有 `ownerId`、`fileId`、`type`、`source`、`status`、`sourceJobId`、`folderId`、`trashedAt`、`deletedAt`；`FileAsset` 保存二进制对象。新增字段和关联关系应优先扩展现有模型，避免另建一张重复资产主表。统一资产至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定资产 ID |
| `ownerType` / `ownerId` | 用户或系统归属；引用某篇内容不等于自动改变文件所有者 |
| `assetType` | `TEXT`、`IMAGE`、`VIDEO`、`AUDIO`、`FILE` |
| `sourceType` / `originKind` | 区分真实生成结果、完成对话引用、主动保存快照、用户上传、参考素材、内容导入和系统素材；不能只靠现有 `GENERATED/UPLOADED/CONTENT_REFERENCE` 推断全部来源 |
| `fileAssetId` | 图片/视频/附件对应的文件资产；文本可为空 |
| `originJobId` / `originUploadId` / `originConversationId` | 生成、上传或对话的可追踪来源；按来源类型择一或组合引用 |
| `title` / `description` | 用户可编辑的展示信息 |
| `metadata` | 尺寸、时长、模型、Prompt 摘要等非敏感元数据 |
| `status` | 对外统一为可用、回收站、清理中、已清理；需映射现有 `DRAFT/SAVED/TRASHED`，`deletedAt` 不能再成为绕过回收站的独立删除入口 |
| `createdAt` / `updatedAt` | 生命周期时间 |
| `systemSourceTag` / `categoryTagIds` | 系统来源事实和分类标签；普通用户只读，具专门权限的管理员可修改分类标签并留审计 |
| `folderId` / `packageItemId` | 用户目录位置与 ZIP 内原始目录位置分开保存；后者只读 |
| `trashedAt` / `purgeAfter` | 移入统一回收站的时间和该项到期时间 |

生成结果和输入参考资料都进入资产模型，但必须保留明确来源，不能把用户上传的参考图、手动创建的文本记录或对话引用误记成真实模型生成结果。数据库层可演进现有 `AiAsset`，也可在迁移中更名为通用 `Asset`；实施时只允许**一个权威资产 ID/状态**，不能建立两份相互独立的 AI 库与工作区库。

**实施模型建议（技术方案，非新增产品决策）：**以现有 `AiAsset.id` 为迁移基点扩展统一资产记录，保留旧 ID 和 `/ai/assets` 兼容；新增明确的 `ownerType=USER|SYSTEM`，用户归属 FK 对系统资产可为空，并用数据库约束保证 USER 必有用户、SYSTEM 不伪装成某个管理员的私有资产。现有 `FileAsset.uploaderId` 记录上传操作者，不作为资产所有权。文本结果新增一对一的受控正文存储记录（例如 `AssetTextBody`），列表只取摘要，详情按 owner 权限读取；现有 `AiAsset.prompt` 不能冒充生成正文。ZIP `PackageItem` 与统一资产采用稳定的一对一映射或明确的引用关系，不能在每次查询时临时生成新资产 ID。随代码发布的 `publicImageCatalog.json` 仍作为只读目录项，不冒充数据库中的可删除资产。最终表名和迁移 SQL 在实施计划中核对现有调用方后确定，但上述归属、正文与 ID 语义不得改变。

## 3. 工作区用户素材库

### 3.1 统一入口

- 入口归属工作区，固定路由为 `/workspace/assets`，不放入主目录工具栏。
- “AI 生产素材”Tab 展示当前用户所有**已成功并已落库**的 AI 图片、视频和文本生成结果；完成的对话回答建立可检索引用并跳到原会话，只有用户主动点“保存到素材库”才生成可独立管理的对话快照。流式生成中的片段、失败任务和仅存在于 mock 的卡片不当作已完成素材。
- 对话引用随原会话/消息的访问和删除状态变化；原会话删除后引用从活动列表移除。用户主动保存的快照保留当时正文、来源会话/消息 ID、模型和时间，是独立资产；以后原会话变化不静默改写快照，删除原会话也不自动删快照。保存动作须幂等，避免连点生成重复快照。
- “我上传的”Tab 展示用户直接上传的附件、普通文件和 ZIP 资料包条目；“参考素材”Tab 展示上传或引用为 AI 输入的图/视频等。一个资产可同时满足“我上传的”和“参考素材”筛选，但只有一个资产 ID，不复制文件。来源徽标写清“AI 生成”“对话引用”“保存的对话快照”“用户上传”“ZIP 导入”“参考素材”。
- 文件列表能看到 `.exe/.dll/.sh/.js/.svg` 等文件：JS/SH/SVG 在格式与扫描允许时以只读、转义的文本源码查看，EXE/DLL 只展示名称、真实类型、大小、来源、路径、扫描状态等元数据；任何文件都不在本站执行。下载须遵守[工作区内容生命周期 PRD](./workspace-content-lifecycle-optimization-prd.md)中的扫描、隔离与强制附件规则。
- 文本结果可以没有 `fileAssetId`，但必须保留文本内容或受控内容引用、来源任务和可检索摘要；超长文本不得在列表接口中无限返回。
- 支持按类型、来源、时间、任务、关键词和目录筛选；默认按更新时间倒序分页。Tab 是来源视图，文件夹是位置视图，两者可以组合，不在切 Tab 时复制或移动文件。
- Chat、Text、Image、Video 的附件选择器最终统一从用户素材库读取；每种工具只展示其模型和权限允许的类型，不允许把任意文本/文件传给只支持参考图的模型。

### 3.2 资产操作

- 预览：图片原图、视频播放器、文本/文件摘要。
- 下载：通过鉴权短期 URL 或服务端下载接口。
- 删除：用户只能把自己可管理的资产移入统一回收站；普通素材列表没有“永久删除”。仍被任务、消息或内容引用时明确提示。彻底删除只能在工作区一级回收站执行，后台全站回收站按管理员权限处理。
- 引用为输入：把资产加入当前工具输入区，保留 `referenceAssetId`，提交时由服务端再次校验权限和状态。
- 再次编辑：回填 Prompt、模型、尺寸/比例、时长及可用参考资产。
- 重命名和整理：普通用户可编辑展示标题、收藏状态和文件夹位置；**不能修改资产分类、来源标签或分类标签**，第一版不做图片编辑和复杂文件夹权限。
- 上传和生成结果由系统按用途/来源给默认分类与来源标签，无法确定时为“未分类”。后台具素材分类权限的管理员可调整分类标签和可编辑分类，需记录旧值、新值、操作者与原因；来源事实、真实 MIME、归属和扫描结果不得作为普通标签直接改写。
- 用户素材库默认不展示后台系统素材；若工具需要选择系统模板或公共素材，使用单独的只读公共资源接口并在 UI 中区分来源。

### 3.3 资产关系

资产需要记录来源关系：

- 生成任务 -> 生成结果资产；
- 用户上传 -> 输入资产；
- 生成任务 -> 参考资产；
- 消息/会话 -> 文本或媒体资产；
- 内容/项目/系统配置 -> 被引用资产。

删除或替换前由服务端检查引用关系，不能只靠前端隐藏按钮。

### 3.4 类网盘的目录浏览

素材库顶部展示面包屑、当前目录搜索和“新建文件夹”；桌面用可折叠目录树 + 文件列表/卡片，手机用面包屑与目录抽屉。允许用户在自己空间创建、重命名、移动文件夹及移动自己资产，目录操作不等于修改系统分类或标签。沿用现有 `AiAssetFolder.parentId` 的树形能力并扩展到非 AI 文件；移动时服务端校验同一 owner、目标未删除、无循环/自身后代、名称冲突及深度上限。非空文件夹删除必须提示处理子项，第一版建议阻止，避免无意把整个目录送进回收站。

ZIP 包内目录是导入时的**只读原始路径**，在资料包详情内以树形目录展示；用户目录是素材库中的**可整理位置**。ZIP 导入不应为每层路径自动创建可编辑用户文件夹，也不因用户移动素材而修改原始 ZIP 路径。资料包条目可在素材库里按来源包与原路径检索；如需“提取到我的文件夹”，应以现有文件项建立新目录引用或明确的复制操作，不悄悄复制 COS 对象。目录浏览第一版不等于通用网盘：公开分享、同步客户端、版本历史、在线协作和任意文件在线执行仍在范围外。

资料包仍在使用某文件项时，素材库不能单独彻底删除底层对象；删除按钮应说明“该文件仍属于资料包”，引导到资料包删除或后续明确的“从包中移除”操作。回收站里也要展示这种引用阻断，不能让素材库先把条目删掉而资料包阅读页留下坏链接。

## 4. 后台管理素材库

- 列出站点系统素材、项目封面、内容封面、后台上传图和被配置引用的资源。
- 支持按用途、来源、文件类型、状态和时间分页筛选。
- 展示来源、用途、引用位置、大小、尺寸、上传时间和当前状态。
- 支持预览、下载、复制短期地址、查看引用关系和安全删除。
- 普通管理员仅可按既有运营权限管理站点素材，**不得读取普通用户私有资产的列表、详情、预览、下载或签名 URL**。系统超级管理员可通过独立“用户私有素材”视图按用户 ID 检索并处理问题；接口须同时校验登录者角色码 `SUPER_ADMIN` 和专门的私有素材访问权限，不能只凭 `DataScope.ALL`、普通管理端登录或前端菜单隐藏。打开用户素材正文/文件、下载、代恢复、分类修改、彻底删除分别记录操作者、目标用户、资产 ID、原因、时间和结果；默认列表先返回必要元数据，不批量暴露全文或私有 URL。
- 随代码发布的占位图通过 `publicImageCatalog.json` 作为只读系统素材展示。
- 后台素材分类操作应有独立权限，不因能登录管理端就自动可改；后端按权限码和数据范围校验，用户端隐藏按钮只是交互提示。
- 系统超级管理员的私有素材视图与[全站回收站](./workspace-content-lifecycle-optimization-prd.md)互通：可从资产状态进入对应回收站记录，回收站中可按用户、类型与原位置反查；普通管理员不能经回收站绕过私有素材权限。

## 5. 文件与存储约束

- 二进制文件继续使用现有 `file_assets` 和 StorageProvider/COS，不在资产表重复存文件内容。
- 厂商临时 URL 必须转存后才能成为长期资产地址。
- 公开页面只拿短期签名 URL；接口响应不返回内部存储路径和私有文件 ID。
- 资产唯一状态流为 `ACTIVE → TRASHED → PURGE_PENDING → PURGED`，`TRASHED → ACTIVE` 可恢复；普通列表只查 `ACTIVE`，统一回收站只查 `TRASHED`，到期/彻底删除由回收站服务推动。现有 `AiAsset.status=TRASHED`、`trashedAt`、`deletedAt` 迁移到同一语义；现有 AI 页内“回收站”筛选改为跳转或展示统一回收站的数据，不维护第二套删除状态。被引用资源不能直接物理删除。
- 用户点删除后资产进入工作区一级目录的统一回收站。已确认默认保留 20 天，后台使用整数天数输入框配置，允许提前彻底删除；回收站恢复/彻底删除、引用阻断、COS 物理清理与失败重试以[工作区内容生命周期优化](./workspace-content-lifecycle-optimization-prd.md)为准，不在素材库里维护第二套清理策略。后台全站回收站可按权限处理用户求助，私有预览需要单独审计。
- 小册转存图片应有真实 `image/*` MIME、`sourceType=CONTENT` 和内容章节引用，供素材查询识别；只有归属或授权满足时才在工作区用户素材库展示，不等同于普通 AI 生成结果。
- 第一版支持图片、视频、文本和普通附件；不做在线裁剪、转码编辑和素材公开浏览页。

## 6. API 草案

| 接口语义 | 说明 |
| --- | --- |
| `GET /api/v1/app/assets` | 工作区当前用户分页查询自己的 AI 结果、附件和参考素材 |
| `GET /api/v1/app/assets/:id` | 查看用户资产详情和引用摘要 |
| `GET /api/v1/app/assets/folders` / `PATCH .../move` | 统一目录树、面包屑与移动；具体路径按 Canonical API 定稿 |
| `PATCH /api/v1/app/assets/:id` | 用户仅修改展示标题、描述、收藏或文件夹；分类与标签字段即使手工提交也要被服务端拒绝 |
| `DELETE /api/v1/app/assets/:id` | 仅移入统一回收站，返回引用影响或阻断信息；恢复和彻底删除只走统一回收站接口 |
| `POST /api/v1/app/assets/:id/resolve-url` | 获取用户资产短期预览/下载地址 |
| `GET /api/v1/admin/assets` | 管理端按权限查看站点运营素材 |
| `GET /api/v1/admin/assets/:id/references` | 查看站点配置、内容和项目引用 |
| `PATCH /api/v1/admin/assets/:id/classification` | 具专门权限的管理员修改分类标签/可编辑分类，记录原因和审计；不改来源事实 |
| `GET /api/v1/admin/user-assets` | 仅 `SUPER_ADMIN` + 专门权限；按用户分页检索私有资产元数据，详情/下载另行授权审计 |

旧 `DELETE /api/v1/app/ai/assets/:id` 上线后必须改为“移入回收站”兼容语义，或返回明确升级错误并引导新接口；绝不能保留可在活跃资产上直接写 `deletedAt` 的路径。旧 `PATCH status=TRASHED/SAVED` 可在过渡期转发统一回收站服务，但要遵守同一到期日、引用检查和审计。最终 DTO、错误码、分页和权限以 Canonical API 为准；用户侧、普通管理端与超级管理员私有视图不能共用不带身份范围的列表接口。

用户库列表接口至少支持 `assetType`、`sourceType`、`status`、`q`、`createdFrom`、`createdTo`、`jobId`、`page`、`pageSize`；默认过滤已软删资产，并按 `updatedAt DESC, id DESC` 稳定排序。文本详情默认返回摘要，只有用户主动打开详情时才返回完整内容。

## 7. 实施阶段

1. 统一资产来源、文件夹和引用关系，补共享类型与 API 契约；先收口旧 AI 资产直删、`TRASHED/deletedAt` 与统一回收站，确保新页面没有两套删除入口。
2. 以现有 AI 页和 `AiAssetFolder` 为迁移基线，完成 `/workspace/assets` 单一管理页面、来源 Tab、目录树、面包屑和文件列表；`/ai/assets` 兼容跳转到 `?tab=ai`，旧链接与收藏可用。
3. 将已完成的 Image/Video/Text 结果、对话完成引用和用户主动保存的独立快照接入统一查询；上传附件、参考图/视频和资料包文件也进入对应来源 Tab。真实媒体能力仍按 `ai-admin` 排期，未完成的结果不得用 mock 记录充数。
4. 工具页统一选择器按模型能力筛文件类型；后台站点素材页与超级管理员私有素材视图分别验收权限和审计，再做引用反查与安全删除。
5. 目录、来源和状态迁移完成后再评估公开分享、文件版本、网盘式同步与更复杂的素材配置选图。

标签体系的**基础能力**必须在第 1 阶段落实：来源标签、分类标签、“未分类”默认值、按标签筛选和管理员分类权限/审计；普通用户只读标签。第 5 阶段之后再评估多层级标签、智能标签及复杂文件夹。现有 `AiAssetStatus.TRASHED` 与 `deletedAt` 在迁移时需统一语义，不能让一项资产出现“列表已删除、回收站又查不到”的中间态。历史资产先只读盘点，再按真实来源补来源标签。

## 8. 验收标准

- 图片、视频、文本和对话结果都能在正确归属下找到。
- `/workspace/assets` 能按类型区分图片、视频、文本、上传附件和参考素材，并能打开文本详情。
- “AI 生产素材”Tab 只包含真实已完成生成结果和明确标识的对话引用/主动保存快照；“我上传的”能看到用户上传与资料包文件，同一文件在多个来源筛选里只有一个资产 ID。
- 目录树能浏览用户文件夹与资料包原路径；用户移动普通资产不改 ZIP 原路径，不能跨 owner 移动或把文件夹移入自己的后代。
- `.js/.sh/.svg` 仅以转义文本或元数据查看，`.exe/.dll` 仅看元数据；扫描未完成/已阻断项目不能借素材库短期 URL 或原 ZIP 下载绕过隔离。
- 上传附件、参考图/视频和生成结果可以互相作为后续输入，但权限不能越界。
- 删除被引用资产时有明确阻断或影响提示，不能留下失效引用。
- 预览和下载走鉴权短期地址，厂商临时 URL 不暴露给浏览器长期使用。
- 工具总页、各工具页、用户资产页和管理端素材库在手机/桌面均无横向溢出。
- 重复任务、重复回调和重复上传不会产生无法追踪的重复资产；所有资产可追溯到来源任务或上传记录。
- 上传时系统赋默认分类（无法判断时“未分类”）；普通用户修改标签请求被拒绝，管理员有专门权限且留审计后可修改分类标签而不改变来源；删除后在统一回收站可恢复，过期或彻底删除后不能再获取短期预览地址。
- 普通管理员直接调用用户私有资产列表、详情、预览、下载、签名和回收站接口均被拒绝；超级管理员的私有素材访问可按资产 ID 找到审计记录。
- 普通列表删除后可在工作区一级回收站找到，资产页不存在直接彻底删除的路径；旧 `/ai/assets` 的批量删除也不能绕过回收站。

## 9. 现有 AI 资产页与新工作区入口

当前已有 `/ai/assets` 页面及 `/api/v1/app/ai/assets` 接口，包含 AI 文件夹、收藏、移入回收站和恢复；`/workspace/assets` 目前不存在。**已确认合并为一个完整用户素材库。** `/workspace/assets` 是唯一管理页面，`/ai/assets` 作为兼容路由跳转到 `/workspace/assets?tab=ai`；AI 侧“资产”导航可继续指向兼容入口。跳转应保留原有深链所需的资产 ID/筛选信息，并在统一页面提供返回 AI 的路径。旧数据只迁移或映射一次，不能复制第二份资产。旧接口可按兼容期逐步转发统一服务，不能继续维护不同的权限或删除逻辑。

接入分三步：先让旧 `AiAsset` 和 `FileAsset` 在新查询中被正确映射，再接新生成任务和上传链路，最后切换各工具的附件选择器。迁移只为确有缺口的历史记录补关系/来源，保持原 `id`、文件 key、归属与时间。若不能从历史记录可靠判断来源，用“历史来源待核实”，不能猜成生成结果。需先只读盘点孤儿 `FileAsset`、重复 `AiAsset`、缺失文件和已 `TRASHED` 项，回填脚本支持 dry-run、批次、审计和重跑。

## 10. 类型、归属与引用的统一规则

| 场景 | 资产记录 | 文件对象 | 列表与删除语义 |
| --- | --- | --- | --- |
| AI 单张图/视频结果 | 每个结果一个稳定资产 ID，关联任务与结果序号 | 原图/视频存 `FileAsset`；封面/缩略图为衍生文件 | 任务失败无可用资产；删除资产不删除任务审计 |
| AI 文本结果 | 一个文本资产，正文独立存储或引用已持久化消息/结果 | 可无文件 | 列表仅摘要；详情经归属校验读取全文 |
| 对话结果 | 回答完成后建立指向原会话/消息的可检索引用；用户主动保存时才建立独立快照 | 可无文件 | 引用随原消息权限与删除状态变化；快照独立管理但保留来源，流式片段不入库为资产 |
| 上传附件/参考图视频 | 上传完成并通过安全校验后建资产，标记上传/参考来源 | `FileAsset` 保留真实 MIME | 未完成上传不出现在普通素材列表；同一文件可被多个来源 Tab 筛出但不复制 |
| ZIP 资料包文件 | 按包 ID 和只读原路径挂接统一资产目录 | 每个可管理条目有受控文件引用，原 ZIP 仍受包权限约束 | 代码文件只读文本，二进制文件元数据；扫描阻断时不可下载 |
| 小册插图/内容封面 | 记录内容引用与归属，保留 `CONTENT` 来源 | `FileAsset` | 默认不自动混入 AI 素材筛选；可见范围由内容权限决定 |
| 站点运营素材 | 系统归属，引用配置或项目 | 文件或随代码资源 | 后台列表展示；随代码资源只读且无删除按钮 |

引用关系至少包含 `assetId/fileId`、引用方类型与 ID、引用用途、创建时间、状态。活跃引用包括生成任务输入、会话消息附件、内容正文/封面、项目/站点配置；生成任务历史只作审计引用，不应永远阻止用户删除展示记录。删除前按引用类型返回“可安全移入回收站”“移入后引用将失效，需确认”“禁止删除直到解除配置/正文引用”之一。数据库引用与 COS 对象生命周期分开：一个文件可被多个资产或内容使用，最后一个活跃引用解除后才可物理清理。

## 11. 页面与交互规格

- 工作区顶部 Tab 为“全部”“AI 生产素材”“我上传的”“参考素材”，类型（图片、视频、文本、文件）、标签、关键词和时间作为 Tab 内筛选；左侧/抽屉是用户文件夹，资料包详情另显示 ZIP 原目录。卡片/列表展示名称、类型、来源、创建时间、原路径或用户目录、缩略图/文本摘要及状态；分类与标签在用户端只读。未知封面有占位，不让失败媒体撑破列表。筛选进入详情/返回时保留 Tab、目录、页码和条件。

## 14. 后端迁移、引用与兼容方案（2026-10-29 补充）

### 14.1 模型落点

本期保留 `AiAsset` 表名与 ID，增加 `ownerType`、`originKind`、来源定位字段、生命周期关联及版本；不同时新建另一张 Asset 主表。`ownerId` 为 SYSTEM 资产允许为空，数据库 CHECK 约束 USER 必须有 owner、SYSTEM 必须无用户 owner。用户素材目录仍用 `AiAssetFolder`，系统素材首版不占用用户目录。

新增 `AssetTextBody`，以 `assetId` 为唯一外键，保存结果正文、格式、正文版本和摘要；列表不加载全文。新增来源唯一约束：生成结果 `(jobId, resultIndex)`、资料包条目 `packageItemId`、对话引用 `(ownerId, messageId, originKind)`。快照以 `(ownerId, messageId, messageVersion, originKind)` 去重，同版本重复保存返回原快照；处于回收站时返回原记录并提示恢复，不能借保存动作绕过恢复校验。快照已彻底清理时旧幂等键只返回已清理结果；如用户重新主动保存仍存在的原消息，使用新操作键和快照代次创建，来源唯一键相应包含代次，不能复活已清理正文。来源不存在或不是完成回答时拒绝保存。

文件保留引用统一交给生命周期 PRD 第 13 节的文件域服务；资产保存文件 ID、内容保存引用、任务保存输入引用，所有新增/解除引用与状态切换须同事务。审计记录只留脱敏来源定位和事件，不把已经删除的正文或文件永久复制到审计表。

### 14.2 历史映射与旧 API

| 原记录 | 迁移行为 |
| --- | --- |
| `SAVED` 且未删除 | ACTIVE，保留原 ID、文件和目录；来源证据不足时标为历史，不能猜成真实生成 |
| `DRAFT` 且未删除 | 保留业务草稿标记；只有完整可展示的结果进入活动素材列表，不伪造生成完成 |
| `TRASHED` 且 `trashedAt` 有值 | 建立统一回收站记录，保留删除时间；迁移期间禁止自动清理，核对后再启用到期处理 |
| `deletedAt` 有值，或删除字段互相冲突 | 进入只读迁移隔离清单；不自动复活、也不自动物理删除；核实对象/引用和原删除语义后再归类 |
| 缺失正文或 COS 文件 | 显示历史数据不可用，保留来源/诊断；不拿 prompt 当结果、不制造空白成功资产 |

迁移脚本按 ID 分页、可续跑、逐条幂等；输出记录数、孤立文件/目录、状态冲突、跨 owner 引用及缺失对象报告。来源回填不得覆盖已人工核实的分类。先发布兼容服务，再回填、切换页面，最后关闭旧写路径；新功能开关关闭时仍可读旧资产。

旧 GET 接口继续提供兼容 DTO；旧 DELETE 统一转成移入回收站；旧 PATCH 的 TRASHED/SAVED 分别调用删除/恢复服务，重复调用不重置保留期。过期或清理中的资产不能通过 SAVED 复活。PATCH 必须返回被修改的资产，不能更新后取列表第一条充当结果。旧入口和新入口共享 owner、扫描、引用、幂等与审计检查。

### 14.3 引用处理的明确规则

- 正文、封面、资料包文件项、站点配置及运行中任务：在引用方解除或任务终止前阻止资产移入回收站，返回可理解的引用类型与数量；不向无权用户泄露其他人的标题或私有 ID。
- 已终止任务历史：保留审计关联，不阻止删除结果；任务详情在结果移入回收站后显示不可用占位，不能重新签发下载地址。
- 会话附件：删除前提示附件将不可用；用户确认后原消息保留占位，移入回收站期间保留文件以支持恢复，不自动改写原消息正文。
- 对话引用：移入回收站仅隐藏该条引用，不删除原消息；完成事件重放不得重新创建已隐藏的引用。原会话删除后引用不可访问；主动保存的快照拥有独立正文，不受原消息删除影响。
- 文件物理删除只由统一清理器执行，回收站项目也算保留引用。先软删资产再立即删 COS 的路径必须清除。

### 14.4 切片验收门槛

契约/迁移切片先覆盖 `schema.prisma`、`ai.service.ts` 的资产入口、文件引用服务与回收站服务、shared-types 和 Canonical 草案，再接工作区与后台页面。禁止素材库和生命周期两个分支各自修改旧删除语义；合并前采用同一状态枚举和引用服务接口。

自动化必须验证：迁移脚本重复跑结果不变；旧/新 API 同 ID 同状态；旧 DELETE 后能在统一回收站查到；旧 PATCH 无法恢复到期记录；生成/对话事件重复只产生一个结果；普通管理员即使 ALL 仍不能列出/签名用户私有文件；超级管理员缺少专门权限仍拒绝；两个引用共享一文件不会误删。浏览器验收覆盖两个用户、普通管理员、超级管理员四身份，从上传/生成到 Tab 展示、删除、恢复、引用选择走完整路径。真实 COS 行为沿用生命周期 PRD 的验证，不另做一套清理验收。
