> 状态：需求细化稿；第 12 节保留少量未决定项，当前未改业务代码
> 最后更新：2026-10-29
> 关系：补充 [小册与文件长期契约](../long-term/content-booklet-file-prd.md)、[用户素材库](./ai-asset-library-prd.md) 和 [工作区产品范围](../../product/workspace.md)。AI 真实生图/生视频仍在 `ai-admin` worktree；本文不改变其厂商协议排期。

## 1. 目标与边界

本轮目标是解决已导入小册图片失效、ZIP 类型错误发现过晚、上传任务与 COS 对象关系不清、新建页类型重置、草稿缺少预览、小册 Markdown 不能编辑、阅读页缺少可靠返回入口，以及两端表格被挤压的问题。新增统一回收站，覆盖工作区内容、可独立删除的文件、用户素材；后台提供保留期限、全站回收站与清理观测。

**ZIP 导入按“资料包 + 可读章节”双层处理。** ZIP 中的普通文件条目都应被识别并保存为受权限控制的文件项；Markdown、HTML、PDF、Word 等合适的内容再关联为可读章节。不能预览的文件只展示类型、大小等信息，并在通过安全检查后提供下载，不执行。只有非可读文件的 ZIP 也能成为资料包，不能伪装成零章节小册；资料包与小册共用一次上传和导入流程，首版以“资料包”为工作名称并在工作区内容列表中展示，见第 12 节。目录层级只用于路径展示、分组和排序，不映射为服务器文件系统目录。

**已确认保留策略：**失败 ZIP 默认保留 7 天，回收站默认保留 20 天；后台两项均使用整数天数输入框配置，允许有权限的用户提前彻底删除。保留期在失败/删除时写入对应记录的 `purgeAfter`，之后改配置只影响新记录，避免已存在项目突然提前到期。输入上下限建议为 1–365 天，实施前可按存储预算收紧；前后端都校验整数与范围。自动任务按 `purgeAfter` 到期清理，界面显示准确到期时间，不把调度延迟描述成“到点立即消失”。恢复后的内容一律回到草稿、私有状态。

## 2. 当前实现基线与已知缺口

| 现象 | 当前代码事实 | 后续改动 |
| --- | --- | --- |
| 掘金图片无法加载 | ZIP 只保存 Markdown，正文外链图片由浏览器访问；`/api/dev/proxy-image` 仅开发 mock 可用 | 图片受控转存与历史补全，不把开发代理搬到生产 |
| ZIP 没有 `.md` | 新建页 JSZip 只预读 `meta.json`；Worker 只接受 `.md`，无章节时报错 | 浏览器选择后预检 + 服务端权威校验 + 混合章节 |
| 失败 ZIP 留在 COS | 上传 `complete` 先把对象记为 READY；导入失败保留源 ZIP 供重试 | 区分可重试/不可重试，按明确期限清理 |
| 上传任务“移除” | 只写 `hiddenFromTaskList=true`；不删 `file_assets` 或 COS；导入任务同理 | UI 改为“从列表隐藏”，另提供“移入回收站/取消重试” |
| 已有内容删除 | `contents.deletedAt` 软删，恢复窗口硬编码 30 天；没有统一回收站与物理清理 | 统一列表、策略快照、清理 Worker |
| AI 资产删除 | 已有 `TRASHED/trashedAt` 与 `deletedAt`，但语义和统一回收站不一致 | 对齐为可恢复删除与最终删除两阶段 |
| 新建页选项 | `initialValue=MARKDOWN`，刷新后丢失用户所选类型 | 路由参数保存类型，仅允许白名单类型 |
| 草稿预览 | 服务端作者/全站读取者可取草稿详情；工作区列表只给已发布项“查看” | 显式“预览”入口和只读标识 |
| 小册章节编辑 | 对象存储中只有 `.md` 正文，章节接口只读 | 加版本化编辑接口；不影响原始 ZIP 审计件 |

## 3. ZIP 资料包、章节与安全策略

### 3.1 识别规则

| ZIP 条目 | 保存与识别 | 前端展示与下载 |
| --- | --- | --- |
| `.md` | 保留原文件字节并识别编码；可读文本关联章节 | Markdown 安全渲染、草稿编辑；原文件可授权下载 |
| `.html/.htm` | 保留原文件；另生成受限的静态预览数据 | “安全预览”尽量保留文字和静态结构；“查看源码”完整显示经过 HTML 转义的源文（含脚本、样式和注释），只读；原文件仅作附件下载 |
| `.js/.sh/.css/.json/.txt` 等文本 | 保留原文件；在大小、编码和内容扫描通过后按纯文本读取 | 只读代码框/文本视图，语法高亮只处理字符串，禁止运行；超限时只展示元数据和下载 |
| `.pdf/.docx` | 校验文件签名与内部结构，保留为文件项并可关联章节 | 复用 PDF/Word 阅读器；源文件可授权下载，不站内编辑 |
| `.png/.jpg/.jpeg/.webp` 等受支持图片 | 校验实际格式后存 COS；被正文引用的图片建立章节引用，其余保留为普通文件项 | 被引用时在正文显示；未引用时在资料包文件列表预览/下载 |
| `.svg` | 原始字节作为文件保存；不按图片渲染，不作为 HTML 注入 | 展示类型/大小及转义后的 SVG 源码；不使用 `<img>`、`iframe` 或同源内联预览，授权时以附件方式下载 |
| `.exe/.dll`、宏文档、嵌套归档及未知二进制 | 不解包内部内容、不运行；保留文件及检测结果 | 仅展示元数据；通过安全扫描后可附件下载，隔离/阻断项只允许有权限管理员处理 |
| 目录、系统噪声文件 | 目录记录层级；`.DS_Store`、`__MACOSX` 等噪声可保留在清单中但默认折叠 | 不作为章节；不让系统噪声占据阅读目录 |

“能导入”与“能预览/下载”是不同状态。可疑扩展名本身不等于恶意文件，`.exe/.dll/.sh/.js/.svg` 不再使整包失败；只有 ZIP 结构不安全、超出硬上限、加密无法检查、路径冲突/穿越、对象损坏等问题才拒绝整包。上传后扫描标记 `PENDING/CLEAN/BLOCKED`：`PENDING` 不开放下载，`BLOCKED` 隔离且仅管理员可调查，普通文件通过检查后可下载。扫描器无法保证绝对安全，UI 只能说明“已检查/已阻断”，不能标“安全无风险”。文件扩展名、声明 MIME 与实际签名/结构不一致时记录真实类型；若无法可靠判断则标“未知文件”，不尝试渲染。

**HTML 尽量完整展示的方案：双视图。** 安全预览只渲染白名单静态标签与安全属性，脚本、事件处理、表单提交、iframe、外链 CSS/资源都不执行；这些内容不丢弃，而是在“查看源码”中以完整转义文本展示。对 `<script>`、`<style>` 等片段可在安全预览相应位置放只读代码块，提示“代码未运行”，但完整性以源码视图为准。很大的源码按段读取/虚拟滚动，不截断原文件；不能在单次 API 响应中无限返回。原始 HTML 文件只以 `Content-Disposition: attachment`、`application/octet-stream`、`X-Content-Type-Options: nosniff` 下载，必要时经隔离下载域名或后端网关，不能给本站同源 HTML 直链；不能承诺复杂网页在无脚本和远程资源下与原站视觉完全一致。JS 与 SVG 也只按文本解析，绝不 `eval`、注入 DOM、用运行时模块加载或同源 iframe 展示。UTF-8 以外文本可在可识别编码下转码预览；无法可靠解码时保留原字节并只提供元数据/受控下载。**站点能保证站内不执行；用户下载后在本机主动打开或运行，已超出站内预览保护范围，下载前需提示文件类型。**

允许一层或多层目录包裹，在规范化的相对路径上自然排序；拒绝绝对路径、`..`、反斜杠歧义、符号链接、硬链接、重复规范化路径、大小写冲突、ZIP 加密条目和异常压缩比。继续保留当前 10,000 条目、8 MiB 元数据、1,000 可读章节、64 MiB Markdown 总量等保护；新增保存文件总字节、单项大小、文本预览字节、HTML DOM/节点数、图片像素、PDF/Word 解析预算和临时磁盘预算。**后台上传大小配置不能放大 Worker 的解析内存/CPU 上限。** 每个条目流式落到隔离临时文件或 COS 暂存 key，不把所有正文同时读进 Node 堆；Worker 不运行归档内任何代码，也不递归解压嵌套归档。

### 3.2 选择文件到导入完成

1. 用户选 ZIP 后，浏览器读取中央目录和少量元数据，展示“预计可读章节数、普通文件数、未知类型数及大小”，不因没有 Markdown/HTML 等可读章节而阻止上传；结构明显非法、条目数或声明大小超限时在上传前阻止。浏览器检查只是节省带宽，不作为安全依据；不在浏览器解压整包正文。
2. 服务端创建上传会话时校验权限、声明大小与用途；`complete` 校验对象大小、ZIP 魔数、SHA-256。此时尚不能可信地断言全部章节合法。
3. Worker 从暂存对象读取并做完整解析、类型/大小/压缩比/路径校验及文件扫描；先把提取文件写到隔离的暂存 key，确认对象存在后，再在数据库事务内切换资料包清单、可读章节、文件项与对象引用。数据库事务无法覆盖 COS 写入；事务失败时清理无引用的新对象，清理失败由幂等任务重试。一个 ZIP 可含不同可读章节和只存储文件。若无可读章节，创建“资料包”而非空小册；清单响应返回类型、标题、相对路径、顺序、预览/下载状态，不返回 COS key 或完整正文。
4. 错误分 `UNSAFE_ARCHIVE`、`LIMIT_EXCEEDED`、`CORRUPT_ARCHIVE`（不可重试）和 `TRANSIENT_STORAGE_ERROR`、`WORKER_INTERRUPTED`（可重试）。单项不支持预览不等于整包错误。任务 API 返回 `retryable`、`errorCode`、可读说明、各类型数量、保留到期时间；前端不凭字符串猜测。
5. 失败 ZIP 不论错误类别默认保留 7 天，后台可配置整数天数；可重试任务在到期前重试不重复上传，不可重试任务保留供诊断或主动删除。历史失败任务在新策略上线前先只读盘点，不按新规则直接删除。

### 3.3 推荐数据模型：资料包文件项与章节分离

建议一个导入结果有一份资料包清单：`ArchivePackage`（关联拥有者、源 ZIP、导入任务、内容记录、状态）和 `PackageItem`（规范化相对路径、原文件名、真实类型、大小、哈希、COS 文件引用、扫描/预览/下载状态、父目录与顺序）。每个普通 ZIP 文件条目都有 `PackageItem`；可读的 Markdown/HTML/PDF/Word 条目再关联 `ContentChapter`，不把 `.exe` 之类塞入“章节”。目录节点可由路径推导，不必给空目录创建可下载文件。现有 `ContentChapter` 仍服务旧小册，迁移采用兼容读；不能直接把每个 ZIP 条目转成章节并假装都支持阅读进度。

有至少一个可读章节的 ZIP 可继续表现为 `BOOKLET`，资料包清单作为附加“文件”页签；零可读章节的 ZIP 建议新增 `PACKAGE` 内容类型，表现为文件列表，不显示空白阅读器、目录或百分比阅读进度。导入默认 `DRAFT + PRIVATE`，继续受现有导入版权限制；**纯文件资料包首版只允许私有保存与本人授权下载，不提供公开/登录可见发布入口，也不进入公开内容审核队列**。后续若开放发布，另补版权、扫描状态与访问配额规则。原 ZIP 留作审计/整体下载，条目文件作为独立 COS 对象供预览与逐项下载，因而存在重复占用；后台应显示源 ZIP、提取对象和转存图片的总占用，后续再决定成功源 ZIP 是否长期保留。

扫描状态字段虽已有 `FileScanStatus` 枚举，但当前代码没有通用的文件扫描流程；**允许脚本/可执行文件逐项下载之前必须先落地扫描、隔离和强制附件下载网关**。没有扫描结果时只能完成受控存储和元数据展示，不能把 `PENDING` 当 `CLEAN`。恶意文件隔离不等于删除，后台可见证据和处置记录，普通用户不可通过源 ZIP 整包下载绕过隔离；源 ZIP 下载也要检查其中是否存在被阻断条目。

扫描服务不可用、超时或返回无法判定时保持 `PENDING` 并安排重试，用户端只显示元数据和“检查中/暂不可下载”；不得因扫描器故障把文件判为 `CLEAN`，也不得通过源 ZIP、旧签名 URL 或其它下载入口绕过。扫描适配层采用哪一实现属于技术选型，是否满足上线门槛以病毒样本、误报处置与网关测试记录判断。

## 4. 外部图片转存、已有小册补全与资产标签

**所有 ZIP 内图片与抓取成功的外链图片最终存入本项目 COS 桶**，通过现有 StorageProvider 写入并登记 `FileAsset`；开发环境可用本地/MinIO 实现，但生产以 COS 为准。ZIP 中未被正文引用的图片仍是资料包文件项，被 Markdown/HTML 引用的图片再建立章节引用，不能因“未引用”而丢失。外链图只收集 Markdown/安全 HTML 中实际引用的地址：先解析规范 URL，仅允许 HTTPS、公开 DNS/IP 和经配置的图床域名；每次重定向重新验证，禁止内网、回环、元数据地址、非图片响应、超时和超限大小，限制并发。图片解码确认类型后保存真实 `image/*` MIME，按内容哈希与权限范围去重；浏览器通过授权代理或短期签名地址读取，私有小册不能通过猜测 COS key 访问。外链图转存失败不应抹去原始 URL/章节内容，而应显示缺图状态并支持后续补全。

历史小册做**显式补全任务**：扫描仍存储的章节源文，先列出外链、已转存、失败数；管理员或作者在权限范围内触发补全，按图片幂等去重，完成后替换章节的引用映射而不破坏原始 ZIP。失败保留原因和下次重试时间；若源站/备份都拿不到图，展示缺图占位和“更换图片”入口，不能承诺自动恢复。上线前用截图中的 `user-gold-cdn.xitu.io` 链接验证服务端能否取得原图及其授权/防盗链要求；若源站不可达，不能只靠生产代理解决。

所有新上传的 `FileAsset`（包括头像、封面、正文附件、ZIP、资料包文件、AI 参考素材）与导入产物均有**系统来源标签**（如 `上传文件`、`小册章节图片`、`AI 参考图`、`AI 生成结果`）和系统默认分类；不能因为头像有标签就把头像暴露到用户素材库。**普通用户不得在上传表单或资产详情更改分类、来源标签或分类标签**；后台管理员可按专门的素材分类权限修改分类标签与可编辑分类，操作需审计。来源事实、文件真实 MIME、归属、扫描结果只由系统产生，管理员也不能将这些事实直接改写成别的来源；纠错须走专门的重分类/重新识别流程并保留旧值。分类未确定时显示“未分类”。标签 ID 与内容业务标签分开；历史资产只读盘点后批量补默认来源标签和“未分类”，不修改原始类型或所有权。图片资产可被未来工作区素材库按 `IMAGE + sourceType=CONTENT` 识别，但仍按归属/授权决定是否可见。

## 5. 上传任务、COS 对象与历史临时对象

工作区「上传任务」展示的是数据库里的文件/导入任务，不是 COS 控制台的对象列表。当前“移除”只隐藏任务行，**不会删除 COS 对象**；后台 `FileAsset` 删除目前也只做数据库软删除，不代表物理对象已删除。**这不等于以后只能去 COS 控制台清理**：服务端已有 StorageProvider `deleteObject` 能力，后续应由受权限保护的删除 API 和清理 Worker 调用。新交互拆成“从列表隐藏”（不改文件/重试状态）、“取消重试并移入回收站”（若无内容引用且任务未运行）、“重试”。运行中的导入任务先取消或等终态；已有内容引用的源 ZIP 不可单独删除。COS 控制台直接删对象会留下数据库引用或破坏重试，不能作为常规清理入口。

后台新增“存储对账/孤儿对象”视图，历史盘点以 `file_assets`、`upload_sessions`、`booklet_import_jobs`、内容/章节/素材引用与 COS 对象清单或 COS Inventory 做**只读对账**，输出：仍在使用、可重试失败、不可重试失败、无任务的 READY 临时文件、过期 UPLOADING、数据库无记录的孤儿对象、数据库有记录但 COS 丢失的对象。按 object key、fileId、jobId、SHA-256、创建时间和最后引用分类；先导出报告并抽样，再对“无引用且超过保留期”分批清理。后台可对单项查看证据、提交清理候选、复核和执行；危险批量操作需要双重确认与审计。删除前二次查引用，COS 删除成功后标记数据库完成；部分失败留待重试。**存量对象先只读盘点，不按新规则自动删。** 不要仅凭文件名、`hiddenFromTaskList` 或 COS 年龄批量删。

未来对象清理采用幂等 Worker：失败/取消的任务进入待清理状态，定期扫描到期且无引用对象；删除失败记录尝试次数、错误摘要和下一次重试时间，后台可看清理积压与失败。**失败 ZIP（可重试和不可重试）默认均保留 7 天**，后台用整数天数输入框配置；超过期限后重试需重新上传。尚未完成的上传会话沿用现有会话到期规则，过期后由清理任务回收对象和未完成分片；成功导入且被资料包/内容引用的源 ZIP 不按失败规则清理。用户主动“取消重试并移入回收站”后按删除时的回收站保留期处理，不能被原失败 ZIP 计时器提前清掉。COS 生命周期规则只用作数据库已确认不再引用的专用临时前缀的兜底，不能覆盖源 ZIP、章节和正式资产前缀。

## 6. 统一回收站

### 6.1 入口与范围

- 工作区一级目录 `/workspace/trash`，默认只看本人可管理的项目；类别筛选：内容（含小册/资料包）、用户素材、可独立删除的上传文件。**后台另设全站回收站**，按用户 ID、类型、删除人、删除时间和到期时间检索以处理用户申诉或程序异常。普通管理员依内容管理权限只看可管理的站点/内容项，不能借回收站枚举或下载用户私有素材；**用户私有素材的回收站记录仅 `SUPER_ADMIN` + 专门权限可见**，打开正文/预览/下载还需记录处理原因并审计。后台同时提供配置与清理结果，工作区普通用户不能进入全站视图。
- 列表显示名称、类型、原位置、删除人、删除时间、到期时间、关联项目数、可否恢复；分页、搜索、筛选。到期或正在清理项不允许恢复。
- 删除动作的默认语义是“移入回收站”；二次确认说明到期后会永久删除。回收站内单项/批量“彻底删除”再次确认“将永久删除，无法从本站恢复”，要求用户主动点击危险按钮；失败项逐项反馈。
- 内容及其章节作为一个回收站单元，源 ZIP 和专属章节资产随内容保留；被其他内容或系统配置复用的图片/文件只有引用解除后才能物理删除。AI 素材被任务、会话或内容引用时，先给出影响说明；仍有活跃引用时阻止永久删除或保留共享文件，不留下断链。

### 6.2 生命周期与恢复

`ACTIVE → TRASHED → PURGE_PENDING → PURGED`；`TRASHED → ACTIVE` 为恢复。记录 `deletedAt`、`deletedBy`、`purgeAfter`、`originalLocation`、`purgeState` 与最近失败原因。删除和恢复要幂等、鉴权并审计；删除时立即从公开列表、搜索、收藏入口和媒体签名接口不可见，旧签名 URL 的最长有效期需在产品提示和安全验收中考虑。回收站项目仍占用存储空间。

恢复到原位置与原归属；原文件夹/分类已不存在时恢复到该模块“未分类”，提示用户；原名称冲突时保留原名但加可区分标识，不覆盖现有项。**内容和资料包恢复后一律为草稿、私有**，并重新校验分类、版权闸与发布权限；不能因恢复自动公开。恢复资产不自动重新插入已经删除的 AI 消息、内容引用或生成任务。用户缺少原对象编辑权限时拒绝恢复并提示管理员处理；后台代恢复须记录管理员、原因和原用户 ID。

Worker 按 `purgeAfter` 分批认领，锁定记录后再次检查引用与状态，再先删除 COS 对象、再提交数据库最终状态；失败保持可诊断状态并重试。多个项目共享同一 FileAsset 时用引用计数/引用查询保证最后一个引用释放才删对象。所有彻底删除都要考虑数据库备份与 COS 版本/备份的独立保留：UI 文案应准确说“本站不可恢复”，不能承诺运维备份在同一秒物理消失。管理员配置页以**整数天数输入框**设置回收站保留期（默认 20 天）和失败 ZIP 保留期（默认 7 天），不使用 7/20/30 选择框；建议 1–365 天范围并在保存时由服务端校验。允许有权限用户提前彻底删除，操作仍须通过引用检查与二次确认；清理频率、批次大小、告警阈值属于运维配置。

### 6.3 开源产品参考与取舍

- [Nextcloud 回收站配置](https://docs.nextcloud.com/server/stable/admin_manual/configuration_files/trashbin_configuration.html)区分保留时长和空间压力清理；本项目采用确定的 `purgeAfter`，不因空间压力悄悄提前清理，空间不足走告警。
- [Nextcloud 管理命令](https://docs.nextcloud.com/server/stable/admin_manual/occ_files.html)将恢复、到期清理和彻底清理分开；本项目同样拆成不同 API/任务，用户“隐藏上传任务”不等同于删除。
- [GitLab 延迟删除与恢复](https://docs.gitlab.com/user/project/working_with_projects/)展示“待删除可恢复、最终删除不可恢复”的状态；本项目恢复时额外降为草稿/私有，避免内容重新公开。

## 7. 阅读返回、草稿预览和小册编辑

阅读页（普通内容详情、小册章节、PDF/Word/资料包）顶栏加“返回”按钮，**视觉和位置参考工作区 Markdown/富文本编辑页顶部的 `ArrowLeftOutlined` 返回按钮**，不参考 AI 页顶栏。站内跳转时将来源路径作为路由 state 或经白名单校验的同源 `returnTo` 保存；按钮优先回到明确且仍可访问的来源。无可信来源、来源为当前阅读页/登录页、或来源已失效时退到 `/content` 内容列表；若内容列表本身无法访问，再退到 `/` 首页。刷新后若来源 state 丢失也按此顺序。不要无条件 `history.back()`，避免回外站或循环回同一章节。返回前阅读进度继续走现有离开同步，不新增频繁上报；手机顶栏留足约 44px 点击区和标题空间。

新建内容类型写入 `?type=BOOKLET|PDF|WORD|MARKDOWN|RICH_TEXT`；刷新、浏览器前进/后退恢复，非法值回退 Markdown。文件选择和表单字段只在用户主动切类型时按规则清空，刷新不把已选类型重置为 Markdown。文件二进制不能跨刷新自动恢复，需提示重选，不伪装成已选文件。

工作区文档列表对本人草稿与授权管理者显示“预览”，走现有服务端草稿可读权限；预览页明确标记“草稿，仅本人/授权管理者可见”，无权用户仍为 404/403。已发布项继续显示“查看”。小册导入成功进入草稿预览，而不是回新建页。Markdown 章节在草稿且有 `content:update` 权限时提供编辑入口，使用版本号/`If-Match` 防覆盖；保存后重算 TOC、字数和搜索字段，更新章节对象时采用新 key + 数据库引用切换，失败回收新对象。保留原始 ZIP 作为导入审计件；编辑不会反写 ZIP。已发布小册修改正文先产生草稿版本并走现有审核/发布规则，不直接改公开版本；PDF、Word、HTML 章节第一版只读。

## 8. 工作区和后台表格横向滚动

截图中的工作区文档管理表把“编辑信息/发布/删除”逐字换行，是表格可用宽度小于列所需宽度。扫描当前页面有 16 个文件使用 Ant Design `Table/ProTable`，其中包括工作区文档、收藏、上传任务、AI 历史，以及后台文档、审核、小册、文件、角色、用户、日志、分类、标签、AI 配置/统计。实施时逐个确认列宽、操作列与现有滚动配置，不靠全局 CSS 给所有表格设一个固定宽度。

表格公共约定：数据列有合理 `width/minWidth`，长标题用省略号与 tooltip；操作列根据动作数给足宽度并保持短文字不拆字；`scroll.x` 使用“各列最小宽度之和”和容器宽度的较大值，窄屏只滚表格内部，页面本身不横向溢出。已有 `scroll.x` 的表保持更大现值；列极少、能自然适应的表也显式验收。固定操作列仅用于确实需要持续可见的宽表，并检查阴影、弹出层和触屏可用性。手机档优先把多操作收进“更多”，不强迫操作列撑满屏幕；桌面可显示完整操作。不要直接给 Ant Table/ProTable 全局默认 `scroll.x='max-content'`，以免短表、嵌套表、虚拟列表和固定列出现回归。

验收视口：390×844、430×932、768×1024、1440×900，以及高度不超过 499 的矮屏。检查表头/单元格对齐、内部横向滚动、分页与工具栏、操作弹窗、批量选择、固定列、页面无横向溢出。截图对应的工作区文档列表必须证明三项操作不再逐字断行。

## 10. 分阶段落地与验收

1. **存量盘点与入口澄清**：增加历史临时对象只读报告、上传任务“隐藏不删除”文案；生产旧对象不删除。浏览器继续按现有 Markdown 规则预检，其他格式提示待新模型上线。
2. **资料包/混合章节与图片**：先完成资料包文件项和章节类型的 migration、旧数据兼容读取、文件扫描/下载网关，再完成 Worker 分类、安全文本预览、PDF/Word 阅读器和图片入 COS；最后打开“所有文件登记导入”与纯非可读 ZIP 上传。验收脚本/可执行文件不运行、HTML 源码完整、无可读章节资料包可查看、旧 Markdown 可读、私有图片不外泄。
3. **工作区阅读编辑**：类型保持、草稿预览、Markdown 章节版本编辑、返回按钮。验收刷新/返回、来源失效回内容列表、草稿权限、并发编辑冲突。
4. **统一回收站与清理**：先打通内容/资料包/文件，再接用户素材；开放后台全站回收站、整数天数配置、存储对账和自动清理。验收管理员代恢复审计、恢复为草稿私有、引用阻断、到期清理重试、数据库与 COS 对账。
5. **两端表格**：逐表修正列宽和内部滚动，按手机/平板/桌面视口截图复核，不混入全局表格样式重构。

最终验收不能只跑单测：需在 MinIO 与真实 COS 的测试对象前缀验证上传、导入、重试、回收、恢复和物理清理；在生产启用清理前先只读盘点并人工核对样本。Nest/API/Prisma 改动按 `fullstack-impact` 文件级计划执行；页面按 `tsx-structure` 和移动响应式规则执行。完成后更新产品范围、Canonical 契约、实现说明与必要的学习文档。

## 11. 明确不做与待验证外部条件

- 不执行 ZIP 内程序，不把未知二进制当可预览内容，不开放通用外链图片代理，不把内容图片无授权地并入用户私有 AI 素材。
- 不保证源站已经失效的历史图片能恢复；需要备份或人工重新提供。
- 不做 PDF/Word/HTML 站内编辑，不用 COS 控制台操作替代系统回收站。
- AI Provider 真实协议、成本和 Seedance 参数仍按 [真实媒体 PRD](./ai-media-generation-prd.md) 单独确认。
- 物理彻底删除后的备份/COS 版本保留属于运维策略，实施前须在部署文档写清实际保留窗口与“本站不可恢复”的用户提示。

## 12. 已确认规则与实施技术取舍

已确认：ZIP 中普通文件都登记保存；仅可读内容进入阅读器；HTML 保留完整源码的非执行查看；脚本/可执行文件可导入但不能执行；新图片存本项目 COS；普通用户不可改分类或标签，管理员经权限校验和审计后可改分类；后台有全站回收站和存储对账；阅读返回按来源 → 内容列表 → 首页；失败 ZIP 默认 7 天、回收站默认 20 天，后台用整数输入框配置；允许提前彻底删除；恢复内容为草稿/私有。

补充确认：**零可读章节的纯文件资料包首版只允许私有保存与本人下载**，公开发布后置。下表其余项是实施建议或需要安全实测的技术取舍，不应误写成用户未表达需求；实施方案可以在不改变上述已确认行为的前提下收口。纯文件 ZIP 暂以“资料包”为工作名称。

| 实施事项 | 推荐方案或已确认规则 | 边界与影响 |
| --- | --- | --- |
| 纯非可读 ZIP 的产品名称与入口 | 叫“资料包”，工作区内容列表筛选；不占小册阅读目录 | 可替换为“文件合集”或单独一级入口，需调整导航与内容类型 |
| 纯文件资料包能否公开 | **已确认：首版只允许私有草稿/本人授权下载** | 公开分享后置；以后开放时补版权、恶意文件下载提示和访问配额 |
| 混合目录排序 | 目录层级 + 文件名自然排序，`meta.json` 有明确顺序时优先 | 是否允许导入后人工调整章节顺序 |
| HTML 预览保真度 | 静态安全预览 + 完整源码视图；脚本/样式片段在预览处显示代码框 | 无法保证依赖 JS/CSS 的网页外观完全一致 |
| 隔离文件的下载 | `BLOCKED` 文件只允许管理员调查，不给普通用户下载 | 若允许用户下载已判定恶意的对象，需单独风险告知与隔离策略 |
| 保留天数输入范围 | 后端和前端统一限制整数 1–365 天 | 上限影响 COS 存储预算，下限影响恢复窗口 |
| 成功源 ZIP 是否长期保留 | 第一版继续保留审计和整体下载；后台显示双份存储占用 | 若清掉源 ZIP，完整重导入与原包下载能力会消失 |
| 文件扫描实现 | 独立扫描适配层；初版可评估自托管 ClamAV 与隔离队列 | 扫描能力上线前只存储/展示元数据，不开放未知/可执行文件下载 |
| 上传类型刷新 | URL 保持类型，文件需重选；非文件表单草稿建议放 sessionStorage | 是否跨刷新恢复尚未提交的文字字段 |

### 12.1 ZIP 校验与安全验收矩阵

- 前端预检负责提前发现中央目录可见的条目数、路径和声明大小问题；选择后在上传前展示预计可读/仅存储数量与拒绝原因。它不能证明压缩数据、魔数或真正内容安全。服务端 `complete` 只确认上传对象完整，**完整格式判定只能在 Worker 读取对象后完成**。页面状态需区分“上传完成、扫描中、正在导入、导入成功/部分文件隔离”。
- HTML 同 ZIP 的相对图片先规范化路径并拒绝越根；外部 HTTPS 图片走第 4 节受控转存。静态预览不应用脚本、外链 CSS、iframe、表单及远程媒体，但原始内容仍在源码视图/源文件中。PDF/Word 的源文件只经授权读取；阅读器失败时该项显示错误和重试，不阻塞其他文件。
- 文件名与内容不一致、同名冲突、加密/损坏、ZIP bomb、路径危险必须给稳定 `errorCode` 和条目级说明；**包含 `.js/.exe/.dll/.sh/.svg` 不是整包拒绝理由**。不得把异常堆栈或 COS key 返回浏览器。解压、正文、预览和临时磁盘分别设固定预算，Worker 需有超时与中断清理。测试含多层目录、混合大小写扩展名、HTML 源码中的脚本、JS 文本、SVG 源码、EXE 元数据、HTML 相对图、无效 DOCX、超限 PDF 和旧版纯 Markdown ZIP。
- 导入失败不能留下半本可见小册或半个资料包。先写隔离暂存对象，再在数据库事务内切换清单与章节引用；COS 写入不在该事务中，失败由无引用对象清理任务补偿，源 ZIP 按配置保留（默认 7 天）。重试同一任务时确认旧暂存对象仍存在，期限已过提示重新上传。

### 12.2 回收站对象关系与权限

| 操作 | 作者/归属用户 | 有 ALL 范围的管理员 | 其他用户 |
| --- | --- | --- | --- |
| 查看回收站 | 只看自己可管理的对象 | 普通管理员仅看授权的站点/内容项；用户私有素材仅 `SUPER_ADMIN` + 专门权限可见，正文另审计 | 不可查看 |
| 恢复 | 需原对象管理权限，且对象未到期/未清理 | 私有素材仅超级管理员可代恢复，记录原用户、管理员与原因 | 不可恢复 |
| 提前彻底删除 | 允许本人在无阻断引用时执行，须二次确认 | 私有素材仅超级管理员可处理并审计 | 不可删除 |

删除内容时先从公开读取、检索、收藏和素材选择器中过滤；已有授权短链通过缩短签名有效期控制暴露窗口。保留 `Content`、资料包文件项、章节、源 ZIP、图片之间的引用图；被多对象引用的 `FileAsset` 不因单个回收站单元到期而删除。恢复仅恢复仍存在的原对象，不凭旧备份自动补全已被独立彻底删除的关联对象。若关联物缺失，应阻断恢复并说明缺项，不生成“恢复成功但打不开”的内容。

### 12.3 分阶段交付门槛

每阶段先更新 Canonical 契约与迁移计划，再同时实现后端、共享类型和调用页面。上线顺序采用读兼容、写新格式、回填历史、关闭旧路径；迁移要能在旧 Markdown 章节仍可读时独立部署。清理 Worker 初次上线只记录“将清理”报告，不执行删除；抽样核对引用后再启用实际删除。以数据库记录、对象存储清单、用户页面三方对账作为物理清理验收，而不只看 API 成功码。


## 13. 后端实施设计与验证门槛（2026-10-29 补充）

本节是可在编码前确定的技术方案，不表示迁移、扫描或 COS 测试已经完成。第 9 节文件清单按以下顺序拆分实施；资料包依赖文件域，统一素材库依赖本节生命周期与引用规则，不能各自维护一套清理器。

### 13.1 增量模型与旧数据兼容

- `ArchivePackage` 关联 `contentId`、`importJobId`、`sourceFileId`、`manifestVersion`；同一次导入任务只允许提交一份生效清单。`PackageItem` 记录 `packageId`、规范化相对路径、`fileId`、识别类型与大小；`(packageId, normalizedPath)` 唯一。路径冲突直接拒绝，不靠覆盖文件解决。
- `ContentChapter` 增加 `format`（旧记录默认 MARKDOWN）和可空的 `packageItemId`；已有 `id/contentId/chapterOrder/objectKey/version` 保留。新 PDF/Word/HTML 从文件项读取，旧 Markdown 继续从 `objectKey` 读取。不得为了迁移重建章节 ID，否则已有阅读记录会断开。
- `PACKAGE` 只在新版服务、共享枚举、两端筛选和详情都能处理后开启写入；服务器对其发布/审核请求统一拒绝，不能只隐藏按钮。旧章节无需重新解压源 ZIP 才能继续阅读；没有可靠源文件的旧小册标为旧格式，不伪造资料包文件项。
- 迁移顺序：新增可空列/表和兼容读 → 更新全部写入入口 → 分批回填并核对数量、ID、章节顺序及阅读记录 → 开启新类型。DDL 由 Prisma 生成并复核；回填使用独立可续跑脚本，不在 DDL 事务里访问 COS。
- 新类型一旦写入，不允许直接回滚到不识别它的旧服务。回退方式为关闭新导入/编辑开关，保留兼容读取；清理任务默认关闭。物理删除不能靠反向 migration 恢复。

### 13.2 扫描与资源预算

技术首选为独立 ClamAV 扫描适配器与隔离队列；病毒检测不替代 MIME、路径、压缩炸弹、HTML 非执行渲染和下载鉴权。扫描结果保存文件哈希、引擎/规则版本、检查时间和错误类别；更换对象后旧结果失效。扫描超限、服务不可用或无法检查均保持 PENDING，不当成 CLEAN。

延续当前解析器硬上限：10,000 条目、8 MiB 文件名等元数据、1,000 可读章节、单 Markdown 2 MiB、Markdown 总正文 64 MiB、压缩比 100、告警最多 100 条。混合导入不能通过换扩展名绕过总预算。新增技术初值：单次文本/HTML 源码预览最多 2 MiB、任务累计文本解析 64 MiB；更大源文件仍可登记存储，预览显示超限并保留通过扫描后的下载入口。HTML 原件不截断保存，预览超限也不能伪装成全文。

原 ZIP、提取文件和派生预览均采用流式传输；临时磁盘按任务申请额度，预计不足时不启动，实际写入逐块计数，超限中止并回收暂存文件。额度由受部署资源约束的 worker 配置给出，不由上传上限自动放大；未配置磁盘额度或扫描容量时，新混合导入开关保持关闭。扫描超时初值每文件 120 秒，瞬时错误最多自动重试 3 次，之后保留 PENDING 并供后台人工重试。生产并发、磁盘额度和扫描容量需用目标机器压测后确定并记录到部署文档。

### 13.3 引用、回收站与物理清理的并发

- 逻辑删除单元用唯一 `(resourceKind, resourceId)` 标识，并持久化生命周期、版本、`purgeAfter`、原位置和操作者；内容/素材记录的旧删除字段只作兼容投影。修改保留配置只影响之后移入回收站的项目，不重算现有到期时间。
- 可恢复内容、资料包条目、资产和配置持有文件保留引用；运行中任务持有临时保留引用；终态任务的历史 ID 是审计关联，不永久保留文件。处于回收站且仍可恢复的引用同样阻止物理清理。
- 恢复和清理认领均锁同一逻辑资源，使用版本条件更新；到期判断用数据库时间。清理成功认领为 PURGE_PENDING 后禁止恢复，恢复先成功则清理任务退出。幂等键和操作结果同事务保存，同键不同请求返回 409。
- 新增文件引用和物理删除认领必须经过同一文件域服务，锁定同一 FileAsset 行；清理再次查全部保留引用后置删除中状态，新引用拒绝绑定删除中的文件。多文件锁按 ID 排序。只在清理前查询一次引用而不阻止新引用是不够的。
- 数据库事务只认领与写任务，不跨 COS 请求持锁。提交后 worker 删除对象，再以认领版本确认完成；COS 删除成功但数据库提交失败时，重试把对象不存在视为删除成功，不重复恢复对象。失效 worker 不能凭旧租约覆盖新任务状态。
- 清理前先释放当前逻辑单元的专属引用，共享文件保留；对象仍有其他保留引用时只完成当前单元逻辑清理。失败 ZIP 到期清理与用户移入回收站也锁同一源文件/任务，不能用旧计时器删除已纳入回收站保留的文件。

### 13.4 可执行验收与启用条件

1. 迁移夹具包含旧 Markdown 小册、旧阅读记录、丢失源 ZIP、混合包和零章节包；迁移前后比较章节 ID、顺序、阅读位置及可见性，失败时关闭新写入仍可读旧内容。
2. 故障注入覆盖暂存 COS 写入成功/数据库提交失败、COS 删除成功/数据库确认失败、重复 worker、恢复与到期同发、新引用与清理同发；断言无活动引用被物理删除，重试不会重复生成章节或回收站记录。
3. 扫描用 EICAR 测试文件、引擎断连、超时和容量超限样本；全部旧/新下载与原 ZIP 入口验证 PENDING/BLOCKED 不能绕过。扫描未就绪可开发存储/元数据切片，禁止开放对应文件下载。
4. 本地 MinIO 验证状态机，真实 COS 测试前缀验证签名/删除/失败补偿，生产先 dry-run 对账再启用清理。只有这部分必须在实现后完成；不把尚未执行写成 PRD 产品决策缺失。
