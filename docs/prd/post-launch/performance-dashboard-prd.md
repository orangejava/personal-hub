## 1. 目标

做一个公开可看的性能面板，用来：

- 展示全站页面加载速度和接口响应时间
- 记录每次优化前后的变化，作为面试展示和日常回归依据
- 让后续首页改版、引入动效库等决定有数据可依

视觉参考 [codexradar](https://deng.codexradar.com/) 的「运行工具 + 模型能力看板」：深色卡片、醒目大数字、按档位着色的小格子、多选标签筛选、折线图、悬停说明口径。

## 3. 基线（2026-09-29 本地 `pnpm build` 实测）

| 资源 | 原始大小 | gzip 后 |
| --- | --- | --- |
| 入口 `umi.js` | 3.86 MB | 1.16 MB |
| 入口 `umi.css` | 60 KB | 12 KB |
| 全部 JS（60 个文件） | 7.4 MB | — |
| 最大异步分包 | 948 KB | 317 KB |

发现：

- 所有页面首屏都要先下载 1.16 MB 的入口 JS。这是当前最大的性能问题，远大于任何动效库的体积。
- 入口里出现了 pdfjs（65 处）和图表库 g2 的代码，但首页不需要它们。
- 高度怀疑的原因：`src/app.tsx` 和 `src/layouts/PublicLayout.tsx` 从 `@/components/shared` 汇总导出文件引入 `PageTransition`，而该文件同时导出 `PdfViewer`、`WordViewer`、`MarkdownViewer`。需要在本 worktree 用 `pnpm analyze` 确认。
- 生产 Nginx（`deploy/nginx/default.conf`）已开启 gzip，并给带哈希的静态资源设置一年缓存。`/api/v1/` 不压缩。HTTPS 仍后置（见 [deploy/domain-https.md](../../deploy/domain-https.md)）。线上要重建 Nginx 镜像后才生效。
- 生产 Lighthouse 不挡住一期。2026-10-10 已在 `http://www.personalhub.center` 测过发版前基线（未开 gzip，入口 `umi.js` 传输约 1.84 MB）。桌面 / 手机各一份：首页 71 / 48，内容中心 71 / 43，小册章节 64 / 41，AI 对话 64 / 42。手机 LCP 为 13.3–20.2 秒。同一张表挂在 `/status` 底部。gzip 上线后再测一轮，接在这张表后面。

## 5. 指标定义

### 5.1 页面指标

阈值采用 Google Web Vitals 的「良好 / 待改进 / 差」三档。

| 指标 | 含义 | 良好 | 差 |
| --- | --- | --- | --- |
| TTFB | 首字节时间，服务器多快开始返回 | ≤ 800 ms | > 1800 ms |
| FCP | 首次内容绘制，用户多快看到东西 | ≤ 1.8 s | > 3 s |
| LCP | 最大内容绘制，主要内容多快出现 | ≤ 2.5 s | > 4 s |
| CLS | 累计布局偏移，页面跳动程度 | ≤ 0.1 | > 0.25 |
| INP | 交互到下一帧的延迟 | ≤ 200 ms | > 500 ms |
| 路由切换 | 站内跳转到新页面挂载后的下一帧 | ≤ 300 ms | > 1000 ms |
| 首屏 JS 传输量 | 首次加载实际下载的 JS 体积（压缩后） | ≤ 300 KB | > 1 MB |

路由切换和首屏 JS 传输量的阈值是本项目自定，不是 Google 标准。

### 5.2 接口指标

| 指标 | 含义 |
| --- | --- |
| 次数 | 统计窗口内的请求数 |
| p50 | 中位数耗时 |
| p95 | 95% 的请求都比这个快 |
| 错误率 | 最终失败的请求占比，口径见下文 |

p95 分档：≤ 300 ms 良好，300–800 ms 待改进，> 800 ms 差（本项目自定）。

接口按「方法 + 路由模板」分组，例如 `GET /api/v1/content/:id`。前端用规则把 UUID、数字 ID 替换成 `:id`，并去掉查询参数。

错误率只统计最终失败的请求：HTTP 非 2xx、网络失败，以及拦截器解包时抛出的 mock 业务错误（HTTP 200 且 `code !== 0`）。Nest 的业务失败本身就是 HTTP 4xx/5xx，会计入。成功解包后的业务对象 T 不计入。不另读响应体里的业务码。一期不采集 `apps/admin-web`。

综合分里的「接口 p95」和抽屉里的「最慢 5 个接口」都用本次会话内存中的最近 500 条。页面 Web Vitals 用 localStorage 里保留 7 天的记录。两套窗口不要混成一个数。

### 5.3 综合评分

面板顶部的大数字，0–100：

- 每个指标先换算成 0–100 分，分段线性插值：
  - 数值 ≤「良好」阈值的一半：100 分
  - 「良好」阈值的一半 → 「良好」阈值：100 → 90 分
  - 「良好」阈值 → 「差」阈值：90 → 50 分
  - 「差」阈值 → 「差」阈值的 2 倍：50 → 0 分；更差按 0 分
- 按权重加权：LCP 25、TTFB 15、CLS 15、INP 15、FCP 10、接口 p95 20。
- 有一条有效样本就计入。没有样本才标「数据不足」，并按剩余权重重新归一。
- 首页摘要的大分数另计。在上面六项之外，再加上路由切换 15、首屏 JS 10。八项都有数时分母是 125。这一分和面板顶部、页面卡片都可以不同。页面卡片仍只看 LCP、TTFB、路由切换。

### 5.4 统计的页面

按路由模板统计，不按具体 ID：

- 公开区：`/`、`/content`、`/content/:id`、`/content/booklets/:id/chapters/:chapterId`、`/projects`、`/about`、`/status`
- AI：`/ai`、`/ai/chat`
- 账号：`/user/login`
- 工作区：`/workspace/dashboard`

新增页面只需在页面清单配置里加一行。

## 6. 一期：前端采集（本机数据）

### 6.1 采集

- **页面指标**：整页刷新的 TTFB、FCP、LCP、INP 用官方 `web-vitals`。INP 不自己用 `PerformanceObserver` 拼。CLS 按当前页累计，不把整次访问的位移记到最后一页；停留约 400ms 后写入，离开页面时立刻收口。站内跳转浏览器不会重报 TTFB、FCP、LCP，所以另记：主区域内容出现的时间当作 FCP 和 LCP，这一跳第一笔新请求的首字节当作 TTFB。没有新请求的跳转仍然没有 TTFB。
- **路由切换**：`app.tsx` 的 `onRouteChange` 在路径变化时记下开始时间。结束点不放在这里，避免把懒加载 fallback 记成已经打开。`PublicLayout`、AI 布局、工作区布局，以及登录 `AuthPageShell`，用 `PerfRouteMarker` 包住页面；子页面提交后的下一帧结束计时。登录不走公开布局，结束点放在登录外壳里。这个外壳也包着注册、找回密码等账号页，但页面清单只有 `/user/login`，其它账号页对不上模板，不写入样本。`getInitialState` 的拉取、401 静默和主题注入保持不动。
- **资源体积**：用 Resource Timing 读取 JS / CSS 的传输大小和耗时，列出最慢、最大的资源。
- **接口耗时**：在 `requestErrorConfig.ts` 的请求拦截器里记开始时间，在响应拦截器和错误处理里记结束时间、状态码和分组名。只加打点，不改原有的解包、错误提示和跳转行为。
- **本机存储**：内存里保留最近 500 条接口记录；页面加载记录写入 `localStorage`，保留 7 天。同一路由同一指标最多 8 条，全局最多 200 条，超出就丢掉最旧的。`localStorage` 不可用或配额满时丢掉这条写入，页面照常使用。

### 6.2 体积约束

- 采集代码会进入口，gzip 后必须 ≤ 5 KB（含 `web-vitals`）；除此之外，面板不能给入口增加任何体积。
- 抽屉和 `/status` 页面必须懒加载。图表库 `@ant-design/plots` 只能出现在懒加载的分包里，不能进入口。
- 本机存储只保存路由模板和指标数值，不保存具体 URL 和用户信息。

### 6.3 界面

**入口范围**：采集在 `app.tsx` 里初始化，覆盖公开页、AI、工作区和登录页。一期的图标只放在 `PublicLayout` 顶栏（首页、内容中心、内容详情、小册阅读、项目、关于、`/status`）。登录、注册等账号页走 `AuthPageShell`，没有公开顶栏，不放图标。AI 页面用的是 `AiLayout`，工作区用的是 ProLayout，一期也不放图标；以后想加，只需在对应布局放同一个按钮组件。

**顶栏图标 → 抽屉（快速视图）**：

- 当前页面的综合评分和各项指标，按三档着色
- 本次会话最慢的 5 个接口
- 「查看完整面板」跳转 `/status`
- 桌面端从右侧打开，宽约 480px；手机端全宽。矮屏（`useViewportBand` 的 `short`，高度 ≤ 499）改为高度 `100dvh`、内容区内部滚动，不用 480px 把抽屉顶出视口。打开时锁定背景滚动。

**完整页面 `/status`**：

- 顶部：综合评分大数字、数据来源标签（一期固定为「本机」）、每 60 秒自动刷新开关、「立即刷新」按钮
- 页面卡片网格：每张卡是一个页面，显示评分和 LCP、TTFB、路由切换三个小格子，按档位着色。有一条有效样本就展示并进入分数。某个指标从未记到才显示「数据不足」，并且不进入综合分，其余指标按剩余权重重新归一
- 多选标签筛选页面，含「全选 / 全不选」；筛选同时作用于下方图表
- 图表：各页面 LCP 随时间变化的折线图、接口 p95 随时间变化的折线图、JS 分包体积柱状图；每张图可全屏
- 接口列表：按 p95 从慢到快排序，显示次数、p50、p95、错误率
- 每个指标名悬停显示口径说明

**风格**：

- 看板表层、边框和文字对比度跟随站点当前有效主题：站点为深色时默认深色看板，站点为浅色时默认浅色看板
- 主色用站点 `colorPrimary`，辅助强调用 `colorSecondary` / `colorAccent`；状态色用 `colorSuccess`、`colorWarning`、`colorError`，不能为了统一颜色而改变「好 / 待改进 / 差」的语义
- 不单独提供面板深浅色开关，也不再把面板主题写入 `localStorage`。用页头「主题设置」切换后，抽屉、`/status` 和提示一起变色
- 抽屉和 `/status` 只读取站点主题 token，不修改站点主题。提示挂在 `document.body` 上，同样带上站点主题变量
- 页面外框、顶栏、间距沿用 `PublicLayout` 和现有公开页

**移动端**：

- 手机档（≤ 767）：卡片单列，图表单列。横滑只发生在图表卡片内部，`body` 不出现横向滚动条。接口列表改为卡片式
- 平板档（768–991）：卡片两列
- 筛选标签可换行，不横向滚动

### 6.4 首轮优化（本 worktree 内完成，用面板验证）

面板一期可用后，立刻做一轮低风险优化，并记录前后数据：

1. 用 `pnpm analyze` 确认入口里有哪些大依赖。
2. `app.tsx`、`PublicLayout.tsx` 改为直接从组件文件引入，不经过 `@/components/shared` 汇总导出。
3. `PdfViewer`、`WordViewer` 等重组件改为在用到的页面懒加载。
4. 对比优化前后的入口体积、首页 LCP 和首屏 JS 传输量，写进实现说明。

### 6.5 一期验收

- 抽屉和 `/status` 在桌面（1440px）、平板（820px）、手机（390px）、矮屏（1280×480）下都能打开。页面外壳无横向滚动条；390px 下若图表需要横滑，只在图表卡片内部滚动。入口增量用 `pnpm --filter user-web analyze` 看 gzip，采集代码 ≤ 5 KB，`@ant-design/plots` 不在 `umi.js` 里
- 在首页、内容中心、小册阅读、AI 对话之间来回跳转后，面板能显示对应页面数据
- 接口列表的分组名正确，没有出现具体 ID
- 用页头「主题设置」在亮色和暗色之间切换。抽屉、`/status` 和提示一起变色，刷新后仍跟随站点主题；站点主题本身不被面板改写
- AI 页面、工作区和登录页的访问也被采集，能在 `/status` 里看到。登录页没有性能图标
- 原有接口的错误提示、401 跳转行为不变
- 入口体积增量 ≤ 5 KB；图表库不在入口里
- 控制台没有新增错误
- 首轮优化前后有数据对比记录

## 7. 二期：Nest 汇总（全站数据）

二期开工前，必须按 [`fullstack-impact`](../../../.agents/skills/fullstack-impact/SKILL.md) 另出一份文件级计划并确认。下面只定范围。

### 7.1 上报

- 前端在页面隐藏时用 `navigator.sendBeacon` 上报 Web Vitals。默认抽样 20%。抽样比例和小时/日数据的保留时长都在后台可配置，不写死在代码里
- `POST /api/v1/metrics/web-vitals`：允许匿名，限流，严格校验字段，只收路由模板和指标数值

### 7.2 服务端耗时

- Nest 中间件在响应结束时记录「方法 + 路由模板 + 状态码 + 耗时」
- 排除健康检查和指标接口自身
- 按分钟聚合到 Redis，用固定区间的直方图（例如 10 / 25 / 50 / 100 / 200 / 300 / 500 / 800 / 1200 / 2000 / 5000 ms）近似计算 p50 和 p95
- 定时任务把小时汇总写入 PostgreSQL；小时数据保留 90 天，日汇总长期保留

### 7.3 发布标记

- 每次部署记录一条版本（Git 提交号、部署时间、备注）
- 图表上用竖线标出发布时间点，「优化前后对比」按发布点前后各 N 天计算

### 7.4 公开范围

- `GET /api/v1/metrics/overview?range=24h|7d|30d`：公开，只返回聚合数据
- 公开面板不显示 `/api/v1/admin/**` 下的接口
- 登录、鉴权类接口只显示分组名（例如「认证」），不显示具体路径

### 7.5 二期验收

- 面板数据来源可在「本机 / 全站」之间切换
- 全站数据在重启服务后不丢失
- 上报接口限流生效，非法字段被拒绝
- 发布标记在图表上可见，前后对比数字正确
- 服务端中间件对正常请求的额外耗时可忽略（单次 < 1 ms）
