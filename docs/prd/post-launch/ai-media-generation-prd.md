# AI 真实生图与生视频 PRD

> 状态：需求细化稿；首批五模型、OpenRouter 聚合 API 和取消计费原则已确定，逐模型端点实测仍待完成；F–G 在 `ai-admin` worktree 实施
> 最后更新：2026-10-29
> 关系：扩展 [ai-admin-operations-prd.md](./ai-admin-operations-prd.md) 与 [long-term/ai-tools-prd.md](../long-term/ai-tools-prd.md)；后台运营配置和厂商协议适配必须分层

## 1. 目标

在现有 AI 图片/视频页面、任务模型和 Fake Provider 基础上，接入第一批真实媒体能力：

1. 先打通文生视频与视频参考输入，再完成真实生图与图片参考输入；
2. 首版纳入第 2 节列出的五个模型，并按实际接入端点的能力开放参数；
3. 统一异步任务、结果文件、失败重试、额度结算和预算约束；
4. 保持页面不直接依赖具体厂商，后续可以替换 Seedance 或增加其他 Provider。

本 PRD 只描述后续真实媒体能力；`main` 手机端 AI 两项修复已完成，不再作为本 PRD 的前置待办。

## 3. 产品体验

### 3.0 现有 mock 字段基线

以下字段和默认值来自当前图片/视频页面 mock，是页面契约的第一版基线；它们描述用户体验，不等同于任何厂商的原生参数。Provider 只能声明支持的字段，服务端在提交前做能力校验，不支持的组合必须返回可理解的错误。

| 能力 | 当前字段 | 当前选项/默认值 | 说明 |
| --- | --- | --- | --- |
| 图片 | `prompt` | 文本输入；默认空 | 必填，服务端限制长度和敏感内容 |
| 图片 | `style` | `科技感`、`写实摄影`、`扁平插画`、`赛博霓虹`；默认 `科技感` | 产品风格标签，是否映射为厂商参数待确认 |
| 图片 | `size` | `1:1`、`16:9`、`9:16`；当前模板默认 `16:9` | 业务比例，Provider 负责转换为尺寸 |
| 图片 | `count` | `1`、`2`、`4`；默认 `1` | 一次任务的结果数量，每个结果独立资产 |
| 图片 | `quality` | `low`、`standard`、`high`；默认 `standard` | 业务画质档位，厂商映射待确认 |
| 图片 | `resolution` | `1k`、`2k`、`4k`；默认 `2k` | 清晰度档位，必须与模型能力联合校验 |
| 图片/视频 | `model` | 当前页面可选择的模型；默认模型由运营配置决定 | 不把模型名写死在前端 |
| 图片/视频 | `attachments` / 参考素材 | 可选图片/视频/文件 | 参考图、参考视频是生成输入；其它文件仅作为普通附件，不能直接透传媒体模型。上传或用户素材库资产需在服务端复核归属和状态 |
| 视频 | `prompt` | 文本输入；默认空 | 必填，服务端限制长度和敏感内容 |
| 视频 | `size` | `16:9`、`9:16`、`1:1`；默认 `16:9` | 业务比例，Provider 负责转换为尺寸 |
| 视频 | `durationSeconds` | `5`、`6`、`8`、`10` 秒；当前模板默认 `6` | 仅允许模型能力声明范围内的值 |
| 视频 | `style` | `产品运镜`、`柔和光线`、`工作台特写`、`电影感`；默认 `产品运镜` | 产品风格标签，是否映射为厂商参数待确认 |

页面已有模板回填、生成中状态、历史任务、媒体详情、下载、再次编辑、重新生成和引用为附件等交互。真实接入必须保持这些交互语义一致；不能因为 Provider 返回异步任务而让页面把“提交成功”误显示为“生成完成”。`style` 可先映射为 Prompt 模板；公开能力没有统一的 `quality` 参数，不能假设两个生图模型都支持该参数，更不能静默丢弃。

### 3.0.1 按模型能力配置输入面板

- 选择模型后，前端读取本站服务端给出的**已验证能力**：输入模式、首/尾帧、参考图/视频的数量/格式/大小/时长限制、比例、分辨率、秒数、输出数量、音频、随机种子、取消能力及价格预估依据。服务端提交时以同一版本能力再次校验，不信任客户端开关。
- 文生图和文生视频默认可选；参考图按模型开放。参考视频仅对完成路由实测的 Seedance 模型开放；HappyHorse 暂不显示参考视频。图片模型不接受视频参考。
- 首帧/尾帧与普通参考图/视频要明确区分。Seedance 2.5 公开说明两者同时传时首尾帧优先，可能让参考素材无效，因此首版面板将其设计为互斥输入模式，切模式时保留已选素材但提交前要求用户确认被排除的输入。
- 切换模型时，保留 Prompt；不兼容的素材或参数在页面显示“当前模型不支持”，要求用户移除或改选后才能提交，不能默默提交不完整请求。能力获取失败时只允许已确认的基础输入，不开放未知参考模式。
- `quality`、风格、精确尺寸、负面提示词、镜头运动、厂商透传参数先列为候选配置。只有对应端点声明并经测试后才显示；运营后台可选择启用已验证的子集，不允许通过配置绕过 adapter 校验。

### 3.1 文生视频

- 用户输入 Prompt，选择模型、比例、时长、分辨率等已被 Provider 声明支持的参数。
- 提交后立即创建任务，页面显示 `QUEUED` / `PROCESSING`，不能假装同步返回视频。
- 任务卡显示 Prompt、模型、比例、时长、创建时间和状态。
- 成功后显示封面、视频预览、下载、查看详情、再次编辑、重新生成。
- 失败显示可读错误；允许按原参数重试，但必须创建新任务并使用新的幂等键。
- 结果可以引用为下一次输入的参考视频或素材附件；目标模型不支持视频参考时只能保留为普通素材。

### 3.2 真实生图

- 沿用现有图片创作流：Prompt、尺寸/比例、数量、风格、模型和参考图。
- 生成中显示任务状态和稳定骨架，不在前端伪造完成结果。
- 成功后支持预览、原图下载、再次编辑、重新生成、引用为附件。
- 多图结果属于同一次生成请求，但每张图都要有独立资产标识，便于下载、删除和引用。
- 两个图片模型都允许参考图；首版参考数量以所选端点实际能力为上限，并同时受本站上传限制约束。

图片页面需保留 `style`、`size`、`count`、`quality`、`resolution`、`model`、Prompt 和参考素材的交互入口；视频页面需保留 `size`、`durationSeconds`、`style`、`model`、Prompt 和参考素材入口。**真实第一版实际开放的字段取决于已验证的模型能力与用户决策**；不支持项应在选模型后明确禁用并说明原因，不能静默降级或提交后忽略。

### 3.3 统一状态

对前端展示的任务状态建议统一为 `QUEUED`、`PROCESSING`、`SAVING_RESULT`、`SUCCEEDED`、`FAILED`、`CANCEL_REQUESTED`、`CANCELED`、`EXPIRED`。其中 `SAVING_RESULT` 表示厂商已生成但本站尚未转存成功，不能显示为成功；`CANCEL_REQUESTED` 表示仍在等待厂商确认或超时收口。是否扩展现有数据库枚举由实现阶段按当前模型决定。厂商状态只能在 Provider adapter 内映射到业务状态。

## 4. 服务端设计

### 4.1 Provider adapter

定义独立的视频和图片 Provider 接口，业务服务只依赖接口，不读取厂商特有字段。adapter 负责：

- 请求参数映射和能力校验；记录所选平台、上游提供方、端点与能力版本，避免模型 slug 相同但路由能力不同；
- 凭据读取、超时和请求签名；
- 创建任务；
- 查询任务或接收回调；
- 下载/转存结果；
- 厂商错误映射、可重试判断和脱敏日志。

后台 Provider 配置负责目录、Base URL、启用状态、模型、价格、默认模型和预算字段；配置成功不代表该厂商已经有可用协议适配器。

### 4.2 异步任务

- 创建请求必须携带 `Idempotency-Key`，同一用户重复提交返回原任务。
- 在接受任务和预占额度的事务里落库，再由 worker 按幂等外部请求提交上游；提交失败先核实上游是否已接受及是否收费，确认未收费后释放预占。不得把数据库事务保持到外部 HTTP 返回，也不能在任务尚未入库时直接发上游请求。
- 统一的**本站任务**可以是异步的，但不要求所有上游协议都异步：若图片端点同步返回图像，worker 在拿到响应后仍按“校验结果 → 转存 COS → 登记资产 → 查询费用 → 结算”推进本站任务；视频端点按上游任务 ID 轮询/回调。同步图片请求超时也不能直接重新生成，应先核实上游是否接收或收费，再按 adapter 能力决定重试。
- worker 负责轮询或处理回调，不能依赖浏览器持续打开。
- 回调和轮询都必须按任务版本/终态条件更新，重复事件不能重复结算或生成资产。
- 任务达到本地超时但上游状态未知时进入待核对状态，先查询任务及费用记录；不能仅凭浏览器断线或生成超时释放额度。确认任务不可恢复后可进入 `FAILED` 或 `EXPIRED`，但费用仍按上游实收结算，只有确认未收费的部分才释放预占。
- 前端轮询只负责刷新展示，不能作为任务推进机制；切换页面或关闭浏览器后，worker 仍应继续处理。
- 状态响应至少返回 `status`、可选 `progress`、参数摘要、错误摘要和资产摘要；进度未知时不展示虚假的百分比。

### 4.3 结果文件

- 厂商临时 URL 不能直接作为长期业务地址；成功后下载到项目 StorageProvider/COS。
- 结果文件写入 `file_assets`，通过鉴权媒体接口返回短期 URL。
- 视频保存原始文件和封面；图片保存原图，缩略图可作为后续优化。
- 任务、资产、用量和额度账本之间必须保留可追踪关联。
- 落库时由系统写入来源标签“AI 生成结果”和默认分类；普通用户不能修改分类或标签，具素材分类权限的管理员可审计修改可编辑分类。参考图/视频和上传附件也必须写入真实文件 MIME 与来源标签，但不能冒充生成结果。
- 用户删除结果时进入统一回收站；引用关系、恢复、到期清理和 COS 物理删除遵循[工作区内容生命周期优化](./workspace-content-lifecycle-optimization-prd.md)，不能因为任务历史仍存在就误删仍被引用的对象。

## 5. API 草案

具体路径、DTO、错误码和权限以 Canonical API 为准，以下是领域边界：

| 能力 | 语义 |
| --- | --- |
| 创建生成任务 | 根据 `toolType` 创建图片或视频任务，要求幂等键 |
| 查询任务 | 返回业务状态、进度、参数摘要、错误和资产摘要 |
| 取消任务 | 记录取消意愿，尝试上游取消并继续跟踪真实费用；不得在未知成本时直接释放额度 |
| 重试任务 | 用原参数创建新任务，保留 `retryOfJobId` |
| 查看结果 | 返回鉴权短期媒体 URL，不暴露内部文件 ID 给公开页面 |
| Provider 测试 | 管理员在测试预算内验证连接和真实参数；若测试请求产生上游费用，记平台测试成本与审计，不扣普通用户额度 |

创建任务请求中的业务字段建议保持稳定：`toolType`、`prompt`、`model`、`size`、`style`、`count`、`quality`、`resolution`、`durationSeconds`、`referenceAssetIds`；参考输入还需区分 `firstFrameAssetId`、`lastFrameAssetId`、`referenceImageAssetIds`、`referenceVideoAssetIds`，且须定义互斥规则。其中图片专属字段和视频专属字段按 `toolType` 校验；不支持的字段不能静默丢弃。厂商原生字段放在 adapter 内部，不能直接泄漏到公共 API。

## 6. 计费与预算

- 视频与图片的预估单位从 OpenRouter 的报价和模型能力获取：视频通常受时长、清晰度和输入模式影响，图片通常受模型、尺寸和数量影响。首版用户实际结算以该任务在 OpenRouter 的实收为准；内部额度若非其计费币种，仅按提交时已展示的固定换算率折算，不额外按“任务成功”或固定次数收费。
- 预占金额以允许的最大成本计算，最终**以 OpenRouter 可核实的费用回执或账单结算**：OpenRouter 未收费则用户不收费并释放预占；已收费则用户承担对应费用，即使用户点击取消。不能把“取消成功响应”“生成失败”或“浏览器停止等待”直接等同于免费。
- 上游费用未返回或账单未确认时进入 `SETTLEMENT_PENDING`（结算子状态，不必强行占用生成任务状态枚举），保留预占并继续核对，前端显示“费用确认中”和最终结果；不可把未知成本写成 0。实际费用超出预占、上游撤销账单或部分成功时按账本补差/退款，使用上游任务 ID + 费用事件 ID 去重。上游收费币种与用户额度单位之间的换算率需在提交时留快照，并在提交前展示预估上限。
- 价格修改只影响新任务，历史 `platformCost` 不回算。
- [AI 后台运营 PRD §5.3](./ai-admin-operations-prd.md)中的 `fixedPlatformCost` 只代表阶段 A–E 既有 Fake/固定价路径；真实媒体不能继续按“成功一次扣固定价”结算。实施时需把费用回执、内部额度换算率快照与预占上限接入现有 `AiUsageRecord`/额度账本，不能新造一套余额。
- 所有变化写入现有额度账本和用量记录，禁止只修改余额。
- 平台预算限制同时检查用户额度、模型单次上限、日/周期预算和 Provider 全局预算。

## 10. 任务状态、取消与重试的完整语义

```text
创建请求 → QUEUED → PROCESSING → SAVING_RESULT → SUCCEEDED
                    ↘ FAILED / EXPIRED
QUEUED / PROCESSING → CANCEL_REQUESTED → CANCELED 或继续收口为 SUCCEEDED/FAILED
```

- “停止等待”只停止前端轮询；“取消生成”是服务端动作。若上游支持取消，adapter 发取消请求并核对任务及账单终态；若不支持，前端提示“已请求停止，仍可能产生费用”，服务器继续跟踪与结算。取消按钮只表达用户意愿，不承诺免费或退款。
- 同一个 `Idempotency-Key` 与同一规范化请求体返回同一任务；同键不同请求体返回冲突。再次编辑只回填参数；重新生成与失败重试都创建新任务、新幂等键，并记录 `retryOfJobId`，不能重用失败任务的额度预占或厂商任务 ID。
- 可重试故障分为厂商限流/5xx、网络、转存失败等；参数不支持、权限、余额不足、内容安全拒绝不自动重试。worker 重试要指数退避、有最大次数、每次先查询原厂商任务，避免网络响应丢失时重复计费或重复生成。
- 取消、回调、轮询和超时同时到达时，以数据库版本和合法状态迁移决定唯一生成终态。结果转存与资产入库需使用任务 ID + 厂商结果 ID/序号做唯一键；费用结算以任务 ID + 上游费用事件做幂等账本。迟到的费用回执可以按对账规则补结或退款，但不能重复扣费；迟到的生成回调不能任意覆写已定的生成终态。
- 任务页提供状态、创建/更新时间、错误类别、重试按钮可用性；未知进度只显示阶段，不伪造百分比。刷新、切路由、手机后台恢复时重新拉服务端任务状态。

## 11. 媒体转存与输入安全

- 参考素材只能提交本系统资产 ID，不接受前端任意 URL。服务端验证 owner、READY 状态、真实 MIME、大小、数量、内容安全与模型能力，再生成厂商可访问的短时受控地址；引用在任务结束前保留，用户删除参考资产时要有阻断或延迟清理。
- 厂商结果下载只能访问该 adapter 验证过的结果域名，重定向逐跳检查，限制响应长度、超时和 MIME/魔数，防 SSRF、超大文件与伪装内容。临时 URL 失效时先尝试厂商重新获取，失败记录为转存失败并允许按规则重试，不把短效厂商 URL 当最终资产。
- 视频保存源视频、封面与元数据（尺寸、时长、编码、文件大小）；封面生成失败时可用占位，但视频本身与结算状态须明确。图片每张独立文件和资产，列表只取缩略图，下载取原图；转码/缩略图失败不能把原件变成不可访问。
- Prompt、参考图/视频与结果的保留、删除遵循用户素材库和统一回收站。后台日志只记任务 ID、模型、耗时和脱敏错误，不记完整 Prompt、用户密钥、厂商响应体或临时 URL。

## 12. 额度、成本与观测验收

一次任务记录**提交时的模型、上游平台/端点、价格版本、参数快照、预占额和用户归属**。预占、结算、释放均写不可变账本并具幂等键；用户余额、Provider 日预算和全局预算在同一任务接受点校验，后台改价只影响新任务。部分成功、厂商已收费但本站转存失败、用户取消但厂商继续生成、厂商免费失败都按上游实际收费结算；本站转存失败仍须保留恢复结果的任务，不可让用户在付费后无从取得成品。未知厂商成本应标“待对账”，不写成 0。

上线前先用 Fake Provider 完成状态竞争与账本测试，再使用测试账号和受限预算跑真实请求。观测至少有：排队时间、厂商耗时、转存耗时、成功率、失败原因、重复事件数、预占未收口数、厂商成本与平台结算差额；异常任务能通过任务 ID 找到来源和补偿记录。验收样例包括：同键双击、创建请求响应丢失、回调早于轮询、重复回调、结果 URL 已过期、两张图一张失败、取消时晚到成功、额度不足、跨用户读取、页面关闭后任务完成、恢复后重新查看。

## 15. 后端费用与异步协议实施方案（2026-10-29 补充）

### 15.1 金额精度与现有账本衔接

`AiUsageRecord.platformCost/providerCost` 当前为 Int，不能直接写 OpenRouter 的小数金额，也不能把旧固定价数值解释成美元。本期扩展费用明细与结算状态，继续使用现有额度账户、预占与账本，不新建第二套余额。

- 上游实收保存 `currency`、`upstreamAmount`（建议 PostgreSQL `numeric(30,12)`）、账单/请求标识和费用证据摘要；输入按十进制字符串解析，计算使用 Decimal，API 返回金额字符串，禁止 JS Number 浮点累加。保留原金额字符串用于核账；上游精度超过字段范围时转人工核账，不静默截断。
- 用户额度仍沿用现有整数最小单位；任务保存提交时的换算率、币种和价格版本。预占按最大预估向上取整；最终按上游累计实收 × 固定换算率计算一次目标额度并四舍五入到最小单位，再与已结算额度做差。重复或部分事件不能逐条向上取整重复收费，退款使用同一快照。
- 未知费用用 nullable 金额及 PENDING 表达，只有上游可核实的零费用才写 0。旧任务标记 LEGACY_FIXED，不倒推历史上游账单、不重算既有余额。检查当前 Int 的上界，预估超界的任务在提交前拒绝，不截断；是否扩容账本列在 `ai-admin` 当前 schema 上重新核对。
- 补差大于可用额度时保留应收差额与对账状态，不让普通扣款路径写非法负余额、不自动免除上游费用；账户存在未收差额时阻止新付费任务，后续额度到账或管理员核账再幂等收口。UI 展示费用与待补差额。退款只通过关联原结算的反向账本记录完成。

### 15.2 状态竞争与上游未知结果

生成状态与结算状态分开存储；新增上游请求 ID、上游任务 ID、结果序号、adapter/能力版本、worker 租约和状态版本。账本事件使用 `(jobId, upstreamEventKey)` 唯一约束；上游无事件 ID 时，以可核实账单版本/累计费用快照生成稳定键，并在任务锁内按“累计目标减已结算”计算差额，不能拿回调到达时间作去重键。累计账单须按上游可验证的修订顺序处理；无法判断新旧的矛盾费用转人工核账，不以更晚到达覆盖已有费用，也不把较小累计值直接当退款。

创建任务、预占、写待执行事件在同一数据库事务提交；worker 只认领已提交任务。调用厂商不放在数据库事务内。创建请求发出后响应丢失时标记待核查，优先凭上游幂等键或请求 ID 查询；如果该端点不支持查询/幂等，不自动再次创建，也不把“尚未拿到 jobId”当作未收费。页面提示核查中并阻止同一请求被自动重发。

用户取消、回调与轮询通过版本检查更新；只有确认未提交上游或上游确认取消才能记 CANCELED。生成超时不代表费用为零；迟到成功结果仍转存到原任务并标明迟到结果，不创建新付费任务，不悄悄丢弃用户已付费产物。已对外确定的终态保留，详情可附结果补全状态及资产入口。

### 15.3 重试、对账与模型启用

查询/转存的瞬时故障初始自动重试 3 次，指数退避并遵守 Retry-After；生成创建是否可重试必须看端点幂等证据，不能套用通用重试。对账技术初值为 1 分钟、5 分钟、30 分钟，之后每小时查询；超过 24 小时进入后台人工核账队列并告警，继续标为费用确认中，不因超时自动释放或认定免费。上游仍在运行时保留查询通道；后台按任务 ID 查看预占、已结、待补差和证据，修正需权限、原因和不可变事件，不能直接改余额。

五模型各自有启用门槛；模型可列为配置草稿，但未通过费用/结果链路验收不得公开提交。参考输入单独设能力开关，基础模式通过不等于视频参考已通过。能力获取失败时只使用服务端仍有效且已验证的版本；不存在可用版本则禁用提交，不能猜测默认支持。真实能力、费率、取消接口不由本节虚构补齐。

| --- | --- | --- |
| 任务状态 | 定义事件、版本竞争、丢响应处置、Fake 场景 | worker 崩溃/重复认领时不重复创建上游任务 |
| 金额 | 定义精度、换算、预占补差、累计去重与退款 | 选定路由的真实账单、取消/失败收费与小数精度 |
| 模型输入 | 冻结五模型候选矩阵及功能开关 | 参考图/视频确实生效，参数边界与账号地区可用 |
| 结果存储 | 定义任务+结果序号唯一键、文件域引用与转存补偿 | COS 转存、过期 URL 恢复及多结果部分失败 |

### 15.4 文件切片与验收

在 `ai-admin` A–E 验证收口的代码上开始 F/G：先核对 `schema.prisma`、`ai-quota.service.ts` 和现有账本实现，新增精确费用/结算明细并迁移兼容；再接 `providers/*`、任务 worker 和转存；最后同时更新 shared-types、两端服务/页面及 Canonical 文档。合并素材库时复用稳定资产 ID 和统一文件引用，不复制额度或资产体系。

无真实凭据时可以完成设计、Fake 和契约开发；真实模型启用仍须受限预算测试。自动化至少覆盖：小数累计不漂移、两次重复费用只扣一次、乱序账单不回退、补差余额不足、迟到退款、取消与成功竞争、创建响应丢失、转存成功而数据库失败。真实验证按五模型记录请求 ID、路由、参数、账单、结果与能力结论，敏感输入/密钥不入文档。回滚先停新任务，保留旧任务查询、转存与结算 worker，不能关停后遗留预占或丢失收费结果。
