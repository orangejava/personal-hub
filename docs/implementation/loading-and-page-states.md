# Loading 与页面等待态

> 状态：代码已落在 `theme-config`，已完成生产验收
> 最后更新：2026-10-16
> 依据：[theme-ui-performance-prd.md](../prd/post-launch/theme-ui-performance-prd.md) §4.3、§5.3–§5.6

## 1. 目标与范围

让首屏、路由切换、列表、小册、AI 生成和后台表格在等待时占住真实内容的高度，并让内容中心、小册、AI、登录表单的等待和失败状态能看懂。

整页等待（首屏脚本、路由分包、带 `fill` 的页面骨架）铺满视口，避免底部露出另一层底色。列表里的小块骨架仍然只占自己的区域。阅读底栏和表单提交按钮在页面数据已经出来之后保持可辨认。

## 2. 加载态

| 场景 | 表现 |
| --- | --- |
| 用户端首次打开 | `loading.js` 在页面包下载前就盖住视口。底部进度按真实阶段走：8%、18%、46%、88%、100%。已经测到的档位仍要从当前百分比走到该档终点，再进入下一档，大约 0.8 秒走完全程，不会一进页面就跳到中途。文件还没到的档位每秒大约前进 8 个百分点，并且不会提前标满。全部档位走完且页面资源已经就绪时立刻进入，不再额外停留。百分比后面的秒数由 `loadingShowElapsed` 控制，关掉后只留百分比。图片、SVG、视频可配动效（不动、旋转、缩放、浮动）。尺寸可选默认宽高或自定义宽高。限制宽高默认 320 像素、最高 480 像素，默认显示和自定义宽高都不能超过它。自定义尺寸在窄屏上再不超过视口的 80% 宽和 70% 高。加载 SVG 只保留图形标签，脚本、外链和 foreignObject 整段丢掉。GIF 只在站点配置的图片上传里开放。站点配置的图片上传含 GIF。视频为 MP4，走已有的 AI 素材上传，不新增文件用途。标题下三道骨架由 `loadingShowSkeleton` 控制 |
| 用户端路由分包 | `src/loading.tsx` 的骨架用固定层铺满视口 |
| 后台路由分包 | 表格行骨架同样铺满视口 |
| 内容列表 | 6 张 16:9 封面卡片骨架，`minHeight` 640 |
| 小册首次进入章节 | 沿用文章骨架 |
| 小册切换章节且旧章节还在 | 正文上方固定一句「正在打开章节」，不把旧正文换成空白 |
| AI 生成中 | 输入区附近固定「正在生成，可以停止当前任务」 |
| 后台列表第一次加载 | 行骨架占住空表高度 |
| 后台列表已有数据后再刷新 | 保留旧行，用表格自己的加载层 |

## 3. 页面交互

- 内容中心：失败文案说明筛选还在、可以重试；有筛选但没有结果时给出「清除筛选」。卡片标题 16px / 600，摘要 13px 次级色。筛选标签允许换行。
- 小册：手机及需要底部栏的窄屏、矮屏，底栏按钮上方显示「阅读进度 N%」。正文底部留白按更高的底栏计算。表格外包一层横向滚动，代码块自身横向滚动。已保存的滚动位置只在再次进入这篇文档时恢复；同一篇里切换章节一律回到顶部。窄屏正文区至少铺满底栏以上的高度，避免滚到头尾时露出另一层底色。
- AI：额度剩余始终可见。图片和视频在 `task.status === 'generating'` 时同样锁住提交，并保留停止。
- 登录、注册、忘记密码、重置密码、修改密码：提交过程中按钮 `loading` 且 `disabled`。登录原有的冷却禁用保留。

## 4. 关键实现

路由 `loading.tsx` 仍然替换页面出口。骨架本身改成 `position: fixed; inset: 0`，把视口盖住，避免只算出内容区高度后底部仍露出空白。

首屏图形和文案写在 `site.general`：`loadingStyle`（`spinner` / `square` / `image` / `svg`）、`loadingTitle`、`loadingSubtitle`、`loadingFileId`、`loadingSvg`。后台站点配置页可以改。公开接口只给出签名后的 `loadingImageUrl`，不给出文件 ID。SVG 只接受以 `<svg` 开头、且没有脚本和事件属性的标记；封面上传不接受 SVG 文件，所以 SVG 用粘贴标记。脚本把最近一次配置记在 `localStorage` 的 `ph.boot.loading`。图片地址大约 8 分钟内可直接用，过期后仍先按「图片」样式占位，等新地址回来再画，避免先闪圆点。请求失败才退回圆点转圈和「正在打开 Personal Hub」。

从内容中心打开小册时，详情页的正文骨架会留到章节地址替换完成；章节页在正文返回前也只用这一套正文骨架。内容列表的路由骨架和页面骨架都是卡片。卡片内部自己的小骨架不改。

后台表格用 `useAdminTablePlaceholder`。还没有行时把 `loading` 设为 `false`，让空状态位置显示行骨架；`onLoad` 看到行之后不再传入 `loading`，后续刷新回到 ProTable 自己的加载层。空数据文案仍是各页原来的句子。

阅读底栏的按钮包在 `.ph-reader-mobile-controls-actions` 里。这层在 `.ph-reader-sheets()` 中是横向撑满的，内容详情页不传进度时，按钮仍然平均分布。
